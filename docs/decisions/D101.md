# D101 · An explanation holds an error raised

Domain. Language.
Decision. The explanation of an error holds the error raised, as it
arrived before `!|` opened it, so it prints with its bang,
`:value ::AddLeftNotNumberError!{…}`, where the explanation of any other
value holds the value as it is [D100]. An error is a value whose walk
passes `::error` [D97], and `explain` raises it the way `raise` does,
under the tag it shows, its trail kept. The container keeps the raised
error [D13], [D87], so `value` hands it on raised, `x !| explain | value
!| type` reading the site.
Source. «а можно сохранить было вид? от print» (maintainer, 2026-09-27
11:10, session d427ce7e) and «не, я хочу что б печаталось с с ! внутри
экспланейшена это можно сделать?» (11:29), answering the model's reading
that the opened error prints as its stack, `::AddLeftNotNumberError::error{…}`,
and declining the model's proposal to declare every refusal a kind of
errors.
Set aside. The opened error under `:value`, the answer of D100, whose
print carries the stack in place of the bang. A print of the
explanation that writes a bang over an error it holds opened, which
reads back as another value [D96]. Each refusal declared a kind of
errors, which the third milestone keeps for the move of the refusing
sites onto kinds [D46].
