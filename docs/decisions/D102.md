# D102 · The library of error pipelines leaves the package

Domain. Language.
Decision. The modules under `core/lib/extras/` leave the package, and
with them the test that loads them. Under an error that is a value of
its kind and a raise that is an act [D97], each of their verbs is a line
of the words every reader already has: `mapError` is `x !| … | raise`,
`withContext` is `x !| union ctx | raise`, `recover` is
`x !| if (pred) handler ~(raise)`, and `assert` and `ensure` are
`if (pred) ~(/) ~(raise {:kind ::Tag …})`; `tap`, `finally`,
`tapError`, `finallyError` and `retry` observe or repeat a pure step,
which answers the same without an effect, and an effect belongs to its
host [D62], whose command line holds `@tap` [D92]. The idioms stand as
examples on the pages of `::error` and `raise`, where `docs` and
`explain` find them. The module resolver of the filesystem stays a
subpath of the package for a host's own libraries, its tests over
modules of their own.
Source. «удаляй так» (maintainer, 2026-09-28 05:16, session d427ce7e),
answering the model's proposal to remove the library whole, `assert`
among it, after the model showed each verb as a line of the core and
asked whether `assert` stays; the audit had left open whether the
library enters the catalog with examples or leaves the package.
Set aside. The library in the catalog on `::error` and `::any`, a
second spelling of what the core writes in a line. `assert` kept as a
short word on `::any`, which the maintainer declined.
