# D103 · A failure of `*` fails it, and an answer the JSON channel cannot carry is refused

Domain. Language.
Decision. `*` runs its body on each element in order, and the first
error the body answers is the answer of `*`, with a stop of its own,
the elements after it left unrun: `[1 "x" 3] * add 10` answers the
refusal of `"x"`. A consumer that wants every element keeps the choice
in the body, `* (add 10 !| 0)` or `* (add 10 !| type)`, so the core
never decides to drop or to keep a failure for it. The elements and
entries of a literal still hold an error a word answers [D87]. The
command line reads its answer against the channel it writes: under
JSON, the channel a JSON input chose, an answer holding a value JSON
has no form for, a quote, a set, a keyword, a tag, a tagged value or an
error inside it, is refused by an error that names the path to that
value and its kind, where the channel wrote a guess, a quote as a
string, a set as an array, a tag as a `$tag` object. The answer that is
itself an error keeps its form, `{"$error": …}`, and every answer keeps
the exit code 0, since a harness that runs calls side by side cancels
the others on a failing one.

an error literal inside a quote, which the ring of atoms builds from a
vector [D42], [D86], and the command line's exit code is chosen for the
harnesses that run it.
Set aside. A literal that fails on the first word that fails, which
waits on what the step of an error literal in a quote is as data. A
nonzero exit code on an error answer, the way `jq` exits, which cancels
the calls a harness runs beside it. A quote refused alone, where every
value JSON has no form for hides the same way.
