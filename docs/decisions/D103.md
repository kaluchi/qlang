# D103 · The first failure of `map` is its answer, and every answer exits with 0

Domain. Language.
Decision. `map` runs its code on each element in order, and the first
failure the code answers is the answer of `map`, the elements after it
left unrun: `[1 "x" 3] | map ~(add 10)` answers the refusal of `"x"`. A
consumer that wants every element keeps the choice in the code,
`map ~(add 10 !| 0)` or `map ~(add 10 !| type)`, so the core never
decides to drop or to keep a failure for it. Every answer of the
command line keeps the exit code 0, a failure among them, since a
harness that runs calls side by side cancels the others on a failing
one.
Source. «про молчаливые сбои и  "ошибки лежат в элементах вектора"
выходит каким-то плохим решением в целом..  fail first может была бы
более честной стратегией или ещё как.. у нас ведь это выразимо текущим
синтаксисом ... типа если надо перехватывать и замалчивать - это можно
сделать выражением каким-то т.е. потребитель решает, а не ядро.. ну или
как-то так.. просто пока мысли мои скорее ... тебе по коду виднее»
(maintainer, 2026-09-28 06:45, session d427ce7e) and «не квота в ответе,
а если вычисленное qlang значение непредставимо в json (на вход ведь
его передали .. а занчит и ждут на выходе тоже json) - то ответ ошибка
.. так можно сделать?» (07:08), after a fresh model's attempt at seven
JSON tasks, in which `/data * /email * lower | distinct | count`
answered `5` from a vector of errors and `groupBy … * ~(* /amount |
sum)` answered the source of the quote as strings. Keeping the literal
out of the rule and the exit code at 0 is the model's, the same day,
from the code: a literal that failed on a word would refuse the step of
an error literal inside a quote, which the ring of atoms builds from a
vector [D42], [D86], and the command line's exit code is chosen for the
harnesses that run it.
Set aside. A nonzero exit code on a failure, the way `jq` exits, which
cancels the calls a harness runs beside it.
