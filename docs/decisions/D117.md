# D117 · A declaration of a noun's module is a member of the noun

Domain. Language.
Decision. A declaration a noun's module makes that is no verb is a
member of that noun: it is read through the noun, `::qlang | docs
:pipeline`, as a verb of the noun is [D88], and it is no name of a
reader's scope, neither a name a query calls nor one `env` lists. The
concepts of the language are members of the root noun, `::qlang`,
declared in its module, `qlang/qlang`, under bare keywords, `:pipeline`,
each with its page. A member has an address as a verb has one,
`::qlang/pipeline`, written short for the root as a kind of the core is,
so `::qlang/pipeline | docs` reads its page and a vector of addresses
reads several, `[::qlang/pipeline ::qlang/errors] * (docs | first |
content)`; the first screen still opens them all by `links * open`.
Source. «почему не ::qlang | docs :concepts и так далее? или мне
показалось что кейворды без своего неймспейса валяются..» (maintainer,
2026-09-28 12:08, session d427ce7e), on the concepts D111 declared
under keywords of the language's namespace in the reader's scope, which
`env` had to be taught to hide.
Set aside. The concepts as names of the reader's scope under a
namespace, which a filter on `env` keeps from sight and a misspelled
verb could still call. A module of the root that is the catalog's root,
`qlang/core`, a second rule where the module of a noun is named by one.
