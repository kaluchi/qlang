# D122 · A snippet is a query a page shows to run and see

Domain. Language.
Decision. A quote under `::snippet` in a doc is a snippet, a query a
page shows its reader to run and see: a listing, `::snippet~(::vec |
spec | /verbs)`, or a demonstration of a form, `::snippet~({:a [5 6]} |
/a/-1)`. It answers whatever it shows, where a law answers true and a
link opens a page [D121]; `snippets` reads the snippets of a doc, and
the suite runs every snippet of the catalog, failing on one that
answers an error. `::snippet` is a kind of the core with a page and no
constructor, as `::link` is, the role a tag gives a quote [D108].
`open` lives on `::qlang/quote` and runs a quote beneath whatever tags
stand over it, so a link and a snippet open alike, and the kind `::link`
keeps its page with no module of verbs. The mentions that D121 wrote as
code in backticks are snippets, checked again.
Source. «слушай, может все таки сделать ::snippet и ::invariant ?   ...
или почему мы отказываемся от них?..» (maintainer, 2026-09-28 14:06,
session d427ce7e), after D121 turned the listings a page linked into
code the suite no longer ran. `::snippet` is the model's answer, the
same day.
Set aside. `::invariant`, a second name for the law a quote with no tag
already is: it answers true and `runExamples` holds it, one check under
two names. A snippet checked by parsing alone, which lets a renamed verb
under it go dead; a run catches it.
