# D125 · A parse error names the bracket left open, and a doc after a step is refused

Domain. Language.
Decision. A parse error that meets the end of its source with a bracket
still open names that bracket and where it opened, and its `:expected`
holds the closers that complete the source, the ones a reader meant:
`[1 2 3] | filter ~(gt 1` answers `:expected [")"]` with the message
that the quote opened at line 1, column 18 is never closed. The parser
finds them itself, parsing the source with each closer appended, so no
class of the grammar is copied into the runtime. A refusal the grammar
writes, a combinator set against its neighbour or a comment opened
against a pipe, looks ahead before it reads, so it adds nothing to the
continuations of other errors. A doc written after a step with no
combinator is refused, where it was the doc value the step handed on:
a note inside a pipeline is a comment, `|~ … ~|`, which is whitespace,
and a doc as a value is piped to, `| |~~ … ~~|`.
Source. «а почему там ожидается doc ?» (maintainer, 2026-09-28 16:40,
session d427ce7e), on `:expected [:whitespace :doc "!|" "|" "*" ")"]`;
«ну а почему не [1 2 3] | filter ~(gt 123 ? или ещё что?...» (16:42);
«ок, давай так, делай» (16:44). The closers found by the parser, the
refusal of a doc after a step and the traps turned to lookaheads are
the model's answer, the same day.
Set aside. The parser's list of alternatives at the failing character,
which misses the digits a number may take, names the combinators it
refuses written flush and a doc that would replace the value. A doc
after a step read as the value it is, which saves one `|` and drops the
answer of the step before it without a word.
