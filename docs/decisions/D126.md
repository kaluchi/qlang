# D126 · `json` writes a set as an array, a keyword as its name, and a value JSON has no form for under its tag

Domain. Language.
Decided by. The maintainer; the forms of a quote, a tag name, a value
under a tag and a failure are the model's.
Decision. `json` writes the JSON text of a value, the conversion a query
asks for where the command line answers in the literal [D214]. A set is
written as the array of its elements in the one order, `#[3 1] | json`
answering `[1,3]`: a set is the vector in the one order without
duplicates [D16], so the array carries all of it but the mark that it
is a set, which the lossy codec of the boundary gives up as it gives up
a map's order of keys. A keyword is written as its name, so the keys of
a map read back as strings, `{:a #[2 1] :b :k} | json` answering
`{"a":[1,2],"b":"k"}`. A value JSON has no form for is written by a form
of its own, never refused: a quote and a doc as their print, a tag name
as its print, `::Box | json` answering `"::Box"`, a value under a tag as
its tag beside its payload, `::Box#1 | json` answering
`{"$tag":"Box","payload":1}`, and a failure the codec meets as
`{"$error": {"$tag": …, "facts": {…}}}`, its facts under the word the
language has for them, where it wrote `descriptor`, a word of the
runtime.
