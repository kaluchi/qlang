# D129 · A slot of code refuses the error its modifier answered

Domain. Language.
Decision. A modifier is evaluated at the call against the subject, and
a slot that takes code alone, a quote or a verb, refuses what the call
computed; the error a modifier answered is refused the same way, by the
refusal of the slot, with that error under `:actualValue` and its tag
under `:actualType`. `[{:a true}] | filter /a` runs `/a` on the vector,
and where it answered `::ProjectionSequenceKeyNotIntegerError`, which
names a key and a vector, it answers `::FilterPredicateNotQuoteError`,
whose page says the predicate is a quote, `filter ~(/a)`. A slot that
takes a value, or code among other kinds, passes the error of its
modifier as it is.
Source. The model, 2026-09-29, under the maintainer's mandate of the
night before, «язык должен нести в себе свою документацю» (maintainer,
2026-09-28 20:25, session d427ce7e), after the example of the command
line's README, `filter /active`, answered the error of a projection that
said nothing of the quote it lacked, the form a reader writes by habit
that [D127] asks a refusal to name.
Set aside. Refusing a projection written in a slot of code before it
runs, since `apply /` hands the quote the subject holds and a name in a
slot of code may hold a quote; a hint appended to the error of the
projection, which would make the error of one step speak of the step
that called it.
The case of [D9] where `apply` answered the error of its modifier,
`5 | apply /nope`, is rewritten to the refusal of its slot.
