# D129 · A slot of code refuses the error its modifier answered

Domain. Language.
Decision. A modifier is evaluated at the call against the subject, and
a part that takes code alone, a quote, a path or a word, refuses what
the call computed; the error a modifier answered is refused the same
way, by the refusal of the part, with that error under `:actualValue`
and its tag under `:actualType`. `[{:a true}] | filter (get /a)` runs
`get /a` on the vector, and where it answered
`::path/IndexNotIntegerError`, which names an index and a vector, it
answers `::vec/filter/predicate/NotPathOrQuoteError`, whose page says the
predicate is a quote or a path, `filter /a`. A part that
takes a value, or code among other kinds, passes the error of its
modifier as it is.
Source. The model, 2026-09-29, under the maintainer's mandate of the
night before, «язык должен нести в себе свою документацю» (maintainer,
2026-09-28 20:25, session d427ce7e), after the example of the command
line's README, `filter (get /active)`, answered the error of a read that
said nothing of the code it lacked, the form a reader writes by habit
that [D127] asks a refusal to name.
Set aside. Refusing a read written in a slot of code before it runs,
since `apply it` hands the quote the subject holds and a name in a slot
of code may hold a quote; a hint appended to the error of the read, which would make the error of one step speak of the step
that called it.
The case of [D9] where `apply` answered the error of its modifier,
`5 | apply (get /nope)`, is rewritten to the refusal of its slot.
Pruned of what [D248] took.
