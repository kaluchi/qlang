# D136 · The keyword of a verb reads the page of its contract

Domain. Language.
Decision. A keyword that names a verb a provider exports reads the
record a call of that name goes through. That record is the contract on
any value when the name has one, and the one verb of the name when a
single kind keeps it. So `:reduce | doc` is the page of
`::qlang/any/reduce`, `:add | doc` the page of `::number/add`, and
`spec`, `source`, `binding` and `runLaws` read the same record. A
keyword spelling a tag's key, `:"::verb"`, and the name of a member of
a noun, `:pipeline`, still name nothing. A refusal of these axes
no longer offers the name it read among the names near it.
Source. «документации не было у reduce ?», «или там 3 дока разных?»
(maintainer, 2026-10-03 14:02 and 14:03, session 87118b06), and on the
proposal to have `:reduce | doc` open the page of the contract, «ок,
давай так» (14:06). The first page teaches "`x | doc` answers the page
of a name". A reader who wrote `:reduce | doc` got a refusal that listed
the three residences and left out the contract, which holds the page of
the fold, and that offered `:reduce` itself as the nearest name.
Set aside. The contract's address added to the refusal, which keeps a
refusal where the reader asked for a page.
Replaces in part [D62], under which a keyword naming a verb was refused
with the addresses where the name lives.

Replaced by [D137], under which the keyword of a verb names nothing and
its refusal leads to the contract.
