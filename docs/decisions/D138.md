# D138 · A map comes apart into its pairs and back

Domain. Language.
Decision. `entries`, a verb of `::map`, answers the vector of the pairs
`[key value]` of a map, in the order of its entries, each key a keyword
as `keys` gives it. A map's elements stay its values [D15]: `map`,
`filter` and `sort` read the values and carry the keys, and `entries` is
the step that makes a key data, for a task that reads a key beside its
value, `{:auth {:port 3000}} | entries | map ~(unionOf /1 {:name (/0 |
toString)})`. The pair is the shape the language already splits a value
into, `[type payload]`, and the one Clojure, JavaScript and Python give a
map's entries.
Source. «давай ты подумаешь и предложишь на выбор решения по работе с
map-ами что не хватает.. и с чем решать задачи было бы сильно проще..»
(maintainer, 2026-10-03 14:52, session 87118b06); «можно и энтрис ввести
если это лучше.. просто хорошо подумай, что идеально будет сочетаться с
qlang» (14:55); «да, исправляй все и делай нормально» (15:28). Clean
readers on three fresh sets of tasks missed the key beside its value
more often than any shape the language left standing.
Set aside. A record per entry, `{:key :value}`, the shape of jq alone,
read by `/key` where the language reads a pair by `/0`; a verb that
writes the key into each value, which `entries` and `unionOf` compose; a
computed key in a map literal, which keeps the literal a literal; and the
key handed to the code `map` runs over a map, a second input beside the
subject.
Replaces in part [D15], which set the pair of `entries` and
`fromEntries` aside for compositions of `*`, `keys`, a soft read and
`indexBy`:
those compositions are the shape the clean readers missed.
