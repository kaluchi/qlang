# D139 · A string names a key wherever a key is taken

Domain. Language.
Decision. Every place that takes a key of a map reads a string as the
key of its text, as `query` and `has` read it and as a path reads
`/"a"`: `minus` and `inter` on a map take a vector or a set of keys,
each a keyword or a string, so `{:a 1 :b 2} | minus ["a"]` is `{:b 2}`.
An element of another kind is refused with its index,
`::map/minus/KeyNotKeywordOrStringError` and
`::map/inter/KeyNotKeywordOrStringError`, where it was left out without
a word.
Source. «да, исправляй все и делай нормально» (maintainer, 2026-10-03
15:28, session 87118b06), after a reading of the whole core found that
`{:a 1 :b 2} | minus #["a"]` answered the map unchanged and `inter`
answered the empty map, while the soft read of a key and `has` read the
same string as the key.
Set aside. The string left out as before, a wrong answer with no
refusal; and string verbs answering for a keyword, which would convert a
value behind the reader.
Replaces in part [D15], whose operand of keys held keywords alone.
Pruned of what [D248] took.
