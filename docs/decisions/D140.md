# D140 · `sort` takes its keys in order, and `desc` turns one to descend

Domain. Language.
Decision. The keys of `sort` are a rest of quotes, `* :keys ::quote`:
the first ranks the elements, and each later key ranks the elements the
keys before it leave alike, `sort ~(/count | desc) ~(/name)` as `ORDER BY
count DESC, name` reads; without a key the elements rank themselves.
`desc`, a verb of any value, lays `::desc` over its subject, and among the
values under that tag the one order runs in reverse, so a key descends
whatever the kind it ranks, a string among them, and the keys after it
still ascend. A key that answers an error answers the call [D87], and so
does a key whose vector holds one, where the vector carried the error
into the order without a word. A quote that answers a vector still ranks
by it element by element, a consequence of the one order [D16], and the
pages teach several keys.
Source. «что с убывающей сортировкой?» (maintainer, 2026-10-03 15:51,
session 87118b06); on the compound key, «1 2 ок, 3 бред... и я не понимаю
самой формы .. зачем передаем квоту с вектором?» (16:10); «ок, делай»
(16:12). The catalog taught the descending order as `sort | reverse`,
which reverses the ties as well, and a descending key as `mul -1`, which
no string takes; clean readers wrote `mul -1`, `-/comments` and `negate`
in their tasks of the top few.
Set aside. A slot of direction on `sort`, one direction for the whole
key; a verb `sortDesc`, a second spelling of the sort; and a short quote
of a literal, `~[…]`, which the maintainer refused.
Replaces in part [D87], whose key of `sort` was one quote.
