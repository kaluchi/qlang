# D144 · The command line names the path a shell made of a query

Domain. Command line.
Decision. A query that fails and begins with a drive and a slash, `C:/`,
which no source of qlang begins with, is the path Git Bash on Windows
writes for an argument that began with `/`. The command line adds a line
to standard error that says so and names the two ways around it: a query
begun with a pipe, `| /data/users`, which the shell leaves alone, and
`MSYS_NO_PATHCONV=1`. The answer and the exit code stay as they were.
Source. «по остатку нужны какие-то мои решения или дальше сам?»
(maintainer, 2026-10-03 18:57, session 87118b06), answered with this
repair among the ones the model takes on its own, and «ок, не будем
трогать» (19:00) on the one left aside. A clean child working a fresh set
with the command line spent ten of its fifty-seven calls on queries the
shell had turned into paths, each answered by a parse error that named
the column of `C:` and nothing of the shell.
Set aside. Undoing the path, which would read a query the reader did not
write; and a refusal of the parser for it, which knows no shell.
