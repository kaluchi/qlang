# D148 · The JSON channel writes a keyword as its name

Domain. Command line.
Decision. Under JSON, the channel a JSON input chooses, a keyword in the
answer is written as its name, the form `json` gives it, as a set is
written as the array of its elements [D126]. A quote, a tag and a value
under a tag stay refused as values JSON has no form for [D103], and an
error keeps its own form.
Source. «ок, давай так» (maintainer, 2026-10-03 20:58, session 87118b06),
after «ешё разок поясли про кейворд и жсон ..» (20:56). The keys of a
map are keywords, so `keys` and the pairs of `entries` [D138] answer
keywords as values, and `echo '{"auth":{"port":3000}}' | qlang 'keys'`
was refused by `::AnswerNotJsonError` where `keys | json` wrote
`["auth"]`; the reader converted each keyword by hand, `keys * keyword`.
Set aside. A keyword kept apart from a string in the output, which no
consumer of JSON can read; and `json` made to refuse the keyword in turn,
which would take a form the verb gives away.
Replaces in part [D103], whose channel refused a keyword.
