# D187 · The children of the benchmark run with the shell's conversion of paths off

Domain. Tooling.
Decided by. The model, at the maintainer's word on its proposal.
Decision. A child of the command line runs with `MSYS_NO_PATHCONV=1` in
its environment, which turns off the conversion by which Git Bash
rewrites an argument that begins with `/` into a path of Windows, so a
query that begins with a path, `qlang '/data/users | segments'`, reaches
the language as written. Its prompt no longer tells it to prefix such a query, and
its record holds the environment it ran in [D26]. The conversion is
the shell's and not the language's: the children wrote the flag as
`export MSYS_NO_PATHCONV=1; qlang …`, a compound command whose `export`
no rule of their tools allows, so the call was refused and the child
spent a call writing it again, in every run of [D7] and [D185]; and a
child that left the flag out met a parse error of a query it had
written right. The page of D186 is measured again under D187, the
friction alone changed.
Source. «поясни это зачем export MSYS_NO_PATHCONV= ?» and «че за ерунда
.. ?» (maintainer, 2026-10-10 22:47, session 22b934f8), on the refusals
the children of the benchmark met; «ок, работай .. я не возвражаю»
(23:21), answering the model's proposal to run the children with the
conversion off and to measure the page of D186 again under it.
Set aside. The `export` allowed among the tools of a child, which keeps
the cost of a prefix the language does not need. A reading in the
language of a path Git Bash wrote, which would carry the shell's
mistake into the core.
Requirements. A child runs with the conversion off and its record says
so; its prompt says nothing of it.
Pruned of what [D248] took.
