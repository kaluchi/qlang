# D190 · The tag of an error is written before its bang, and `:kind` is a fact like any other

Domain. Language.
Decided by. The maintainer; the removal of the host's reader of a tag
under `:kind` is the model's.
Decision. An error literal takes its tag from before its bang,
`::Foo!{…}`, and the kind of errors when none stands there; `raise`
takes the tag its value shows, the outermost the walk passed, then the
one the map carries, `::Foo{…} | raise`, then the kind of errors. A
`:kind` entry names no tag in either: it is a fact of the error as any
key is, `!{:kind ::Foo} | [type /kind]` answering `[::error ::Foo]`, as
[D61] ended the reading of a map's `:kind`. The core hands a host no
`errorFromKindDescriptor`, which made an error of the tag a descriptor
held under `:kind`; a host makes one by `makeErrorValue` with its tag.
Source. «второе написание !{:kind …}; - с этим разберись уже.. а то не
первый раз оно мне попадается...» (maintainer, 2026-10-11 01:14,
session 22b934f8), after the outside audit read again at 68af9ab5
named the second spelling, as the first had at 401046d
(`docs/research/outside-audit/`).
Set aside. A `:kind` refused in an error literal, which keeps a word
reserved for a spelling the language no longer has. The host's reader
kept beside `makeErrorValue`, a second way to make an error of a tag.
Replaces in part [D86], under which the tag of an error fell back to a
`:kind` that names a tag.
Requirements. `!{:kind ::Foo}` and `{:kind ::Foo} | raise` answer
errors of the kind of errors whose facts hold `:kind ::Foo`, and
`::Foo{:a 1} | raise` an error of `::Foo`.
Pruned of what [D205], [D211] took.
