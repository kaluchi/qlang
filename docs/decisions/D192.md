# D192 · Under JSON, the refusal of an answer JSON has no form for holds the answer's literal, and an error's JSON writes its facts under `facts`

Domain. Command line.
Decided by. The model, within the maintainer's leave on the findings of
the outside audits, keeping his rule of [D103].
Decision. The command line still answers JSON to a JSON input and
refuses an answer holding a value JSON has no form for [D103], and the
refusal now holds the answer as its literal under `:printed`, beside the
path and the kind of that value: `echo '{"users":[1]}' | qlang '| /users
| type'` answers the refusal whose facts hold `"printed": "::vec"`, so a
query that asks after a kind, a page or a tag reads its answer on that
channel, where the refusal named the kind alone and the answer was
lost. An error written as JSON holds its facts under `facts`, the word
the language has for them, where it wrote `descriptor`, a word of the
runtime: `{"$error": {"$tag": …, "facts": {…}}}`.
Source. The second outside audit, at 68af9ab5: the command line breaks
the exploration of data the first page prescribes, `| type`, `keys |
first | type`, `doc` and `manifest` all refused on a JSON input, and the
reader sees the inner name `descriptor`; the maintainer's leave on what
the audits found beyond the trap of the kinds' names, «остальное реши
сам, ты лучше меня проект знаешь» (maintainer, 2026-10-11 01:43,
session 22b934f8), and his rule that a JSON input expects JSON back,
«если вычисленное qlang значение непредставимо в json (на вход ведь его
передали .. а занчит и ждут на выходе тоже json) - то ответ ошибка»
(2026-09-28 07:08, session d427ce7e), which the decision keeps.
Set aside. The answer written as its literal when JSON has no form for
it, or a flag that chooses the form of the output, as the audit
proposed: a consumer that piped JSON in reads JSON out, and an answer it
cannot parse breaks it where a refusal it can read does not.
Replaces in part [D103], under which the refusal named the path and the
kind alone.
Requirements. Under JSON, the refusal of an answer holds `:printed`, the
answer's literal, and an error's JSON holds `facts`; the command line's
tests hold both, since a query of the suite does not reach the channel.
Replaced in part by [D214], under which the command line writes every
answer as its literal whatever its input was, and a query converts it.
