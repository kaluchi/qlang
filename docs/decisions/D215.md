# D215 · A query that reads no subject does not wait on standard input

Domain. Command line.
Decided by. The model, at the maintainer's word to decide on the way
what the assessment of the command line left open.
Decision. The command line reads standard input only for a query that
reads its subject. A query whose first step that declares nothing is a
literal of no parts or a quote, or a literal whose parts read no
subject, `1 | add 1`, `::vec | doc`, `[1 2] | sum`, runs at once, and
`in` reads standard input when it is called; `readsItsSubject` tells
it from the parser's tree, a node it does not name counting as one that
reads. A query that reads its subject reads standard input to its end,
as every reader of a pipe does: a slow producer, `curl` over a network,
is waited for, and no time decides that an input is empty, so where a
shell hands an open pipe nothing writes to, such a query waits as `jq`
and `awk` do, and `< /dev/null` ends the wait.
Source. The assessment of the command line as the children of the
benchmark met it: `qlang '1 | add 1'` with no input waited until the
shell's timeout, and the rules of the runs told every child to pass
`< /dev/null`, which hid the wait from the measurement. In session
22b934f8 the shell of Claude Code handed every command a pipe, which
`fstat` does not tell from `sleep 10 | qlang`, and a read of it ended
at some calls and never at others, so nothing read from standard input
tells an empty input from a slow one; a query that reads no subject
needs no input at all, as an `awk` program of `BEGIN` alone reads none.
The maintainer, on the open questions written to the audit: «не надо
ничего откладывать ... открытые вопросы (stdin, на что высаживаем
модель) — в аудит,» (maintainer, 2026-10-11 20:17, session 22b934f8)
and «сразу решай все по пути» (20:17).
Set aside. An input that sends no byte within a short time read as
empty, which reads a slow producer as no input and answers a query over
nothing, a wrong answer with no sign of it; the same only where the host
is told a model reads, which keeps that wrong answer for the model; a
character device read as nothing piped, which the pipe of the shell is
not.
Rests on [D37], under which the command line starts from the standard
input when it carries bytes.
Requirements. `readsItsSubject` answers false for each literal of no
parts, a path among them, a quote, a literal of parts that read none
and a declaration before such a step, and true for a call, a part that
reads, a declaration whose body reads and a query of declarations
alone; the command line answers a query that reads no subject over a
standard input that never ends, `in` reads it when called, and a query
that does not parse is refused without reading it.
