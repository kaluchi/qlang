# D219 · A failure prints as its error at rest, under a line that says it was raised

Domain. Language.
Decided by. The maintainer, on the alternatives the model laid out.
Decision. A failure prints as its error at rest, the literal `!|`
grounds it to, `::proj/KeyNotInMapError!{…}`: a value that stands in a
vector or a map and reads back as the error at rest. The answer of a
host that is a failure, which a host meets alone since a step skips it,
prints under a line comment that says so, `|~| raised, and no !| caught
it`, which a reading of the literal passes over, so the reader sees that
the query failed and a paste of the print gives the value. `printAnswer`
writes the line, so every host, the command line, the REPL and the
sister project, prints it; `printValue` prints values alone, and an
error at rest an answer gives prints under no line.
Source. Of the print of a failure: «это не литерал - оно никуда не
встает ни в вектор ли в мэп ... это не печатная лительная форма как по
мне..» and «я бы просто написал что ошибки перед printValue спускаются !|  для
их печати ... или мы теряем важный сигнал так? .. даже если так.. можно
спускать и заворачивая/перепаковывая в какой ::uncaught или что там...»
(maintainer, 2026-10-11 21:57, session 22b934f8); on the model's
alternatives, «хорошо, тривия вариант интересен, давай опробуем - там
все рано рано или поздно делать | legeng  или !| / | legend  - c
форматированием и аннотированием значений содержимым каталога..»
(22:04).
Set aside. The error at rest raised, `::Tag!{…} | raise`, a query and
no literal; the error at rest with no line, which loses that the query
failed while its exit code is 0 [D96]; a wrapper, `::uncaught` or
`::raised`, a kind made to be printed, which reads back as a value of
another kind and wraps again a wrapper a later failure holds among its
facts.
Replaces in part [D211], under which a failure printed as its error at
rest followed by `| raise`.
Requirements. A failure prints as its error at rest, and its print
under `| raise` raises it back; the answer of a host that is a failure
prints under the line, an error at rest under none; the command line
writes the line above a failure and the prose of its page below. The
expectation of a failure in the conformance suite stays its error at
rest raised, a query that answers the failure, apart from its print.
