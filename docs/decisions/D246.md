# D246 · A pattern of text is a value of its own, `#"…"`, read as written

Domain. Language.
Decided by. The maintainer, the literal `#"…"` and a pattern written
without escapes; the kind, its flags, its dialect, its place in the one
order and the words that read text by it are the model's.
Decision. A pattern of text is a value of the kind `::regex`, written
`#"\d+ms"`: what stands between the quotes reaches the engine as it is
written, a backslash with the character after it, so `\d` is a digit and
`\"` a quote that does not end the literal. The flags `i`, `m` and `s`
may follow the closing quote, `#"error"i`, each once, and print in that
order; the pattern always reads text as Unicode does, by code points,
`#"\p{L}+"` a run of letters. The dialect is ECMAScript's of 2018, which
every engine the core runs on reads alike: a group of flags, `(?i)` or
`(?i:…)`, and a group name written twice, which only later engines read,
are refused on every host. Its one limit is the same everywhere: a
pattern whose matching backtracks without end runs as long, the language
bounding no match. A source that is no pattern is refused by the parser,
as a number past the doubles is, with the reason, the engine's words
without its literal, and the repair of the habit of another dialect
where the source shows one, read from the source alone: flags written
inside it, or a backslash before a character that needs none.
A pattern prints as its literal and reads back; JSON writes that literal
as a string, which `parse | apply /` reads back; two patterns are equal
when their text and their flags are; the one order ranks the patterns
after the strings, by their text and then their flags.

A pattern is no string, so a word that reads text tells a pattern from a
text by its kind: `split "."` cuts at a dot and `split #"[.,]"` at either
mark. The words of a string that take one:

- `contains` asks whether a match stands anywhere in the text,
  `"took 12ms" | contains #"\d+ms"`; a pattern anchored by `^` and `$`
  asks it of the whole text;
- `match` answers the first match as the vector of its text and its
  groups, a group that took no part `null`, or `null` where none stands,
  `"took 12ms" | match #"(\d+)ms" | /1` answering `"12"`;
- `capture` answers the groups the pattern names in its first match as a
  map, `"2026-10-12 ERROR down" | capture #"(?<date>\S+) (?<level>\w+)"`
  answering `{:date "2026-10-12" :level "ERROR"}`, or `null` where none
  stands, and refuses a pattern that names no group;
- `scan` answers the text of every match, `[]` where none stands;
- `replace` puts a text in the place of every match of a pattern or of
  a text, read by code points either way: a string given, in which `$1`,
  `$<name>` and `$&` name the parts of a match of a pattern, and a text
  pattern's replacement stands as written, or code, which runs on the
  vector `match` answers for the match and answers the text that stands
  for it;
- `split` cuts at every match, the pieces between the matches alone;
- `toRegex` reads a string as the source of a pattern, its flags the
  part the call gives, none by default, `"error" | toRegex "i"`, and
  refuses a text that writes the literal of a pattern whole, the text
  JSON writes, whose reading is `parse | apply /`.

A pattern has no `toString`: its text is its literal, which `print`
writes.
Source. The open question of regular expressions, which every outside
audit names, and the maintainer: «регулярки надо думать как внедрять ..
хотелось бы что без эскейпинга они были .. но тут ты спец...»
(2026-10-12 19:57, session 014e5a04), «Литерал #"…" - ок(остальное ты
лучше меня знаешь свои прайоры и свои ожидания и вкус матчашийся с qlang
эмержентно согласовать)» (20:12), and «вложи там всю свою душу и талант в
нормальную реализацию регекспов.. что б мог гортиться и получить похвалу
от стороннего аудитора» (20:15). The literal is Clojure's, `#"\d+"`, read
as written; the words follow the readers' priors: `match` as JavaScript
answers its first match, `capture` and `scan` as jq and Ruby name theirs,
`replace` as every language with the replacement syntax of JavaScript.
The model's review of 13 October 2026
(`docs/research/reviews/2026-10-13-the-open-questions-walked.md`) found
the engine of Node 24 reading groups of flags and group names written
twice, the refusal quoting the engine's literal with its hint read from
V8's words, and a pattern JSON wrote read back by `toRegex` as another
pattern in silence.
Set aside. A pattern written in a string, `"\\d+"`, which doubles every
backslash and makes `split "."` cut at every character. `matches`, whose
readers split between a match anywhere and a match of the whole text.
Flags written inside the pattern, `(?i:…)`, which not every engine the
core ships to reads. A dialect that grows with the engine of each host,
under which a literal parses on one host and is refused on another. One
word answering a vector or a map by the groups a pattern names, where
`match` and `capture` answer one kind each. A pattern's `toString`, which
would drop its flags. JSON writing a pattern's source, which drops its
flags in silence, and `toRegex` reading a literal by its look.
Rests on [D30], under which every value prints as a literal that reads
back, and [D244], which names `toRegex`.
Requirements. The cases that name D246 in
`core/test/conformance/42-a-pattern-reads-text.jsonl`, and the laws of
`::regex` and of the words of a string that take a pattern.
