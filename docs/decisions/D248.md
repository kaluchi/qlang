# D248 · A step is a command and a path a value, which the word that takes it reads: `get`, `query`, `has`, and `it` for the value itself

Domain. Language.
Decided by. The maintainer: a step a command and a value the subject or
the object of a word, a path a value that does nothing by itself and
that the word taking it reads, the quote gone where a path is the whole
code, the slash alone gone and `it` for the value itself, `get` reading
strictly, `query` softly and `has` asking, `paths`, and the kind named
`::path`. The model's: the refusal of a value written as a later step
and the words it names, its print and its place in the one order, the parts that
take a path, the literal of paths under `get`, the selectors, `ok`, and
`at` leaving.
Decision. A step is a command, a word and its objects [D10]. A value
stands at the head of a query, of a group and of a quote, and after a
declaration, which ends what the steps before it said, where it is the
subject the steps after it read, `:inc ~(add 1) | 5 | apply inc`, and as
the object of a word. A
value written as a later step on the success track, a path, a literal, a tag
name or a constructor, a quote or a doc, is refused by the parser, which
names the word the habit meant: `get` for a path or a literal that holds
one, `tag` for a tag, `apply` for code. After `!|` a value is the
recovery the catch answers, `"x" | add 1 !| 0` answering `0`, but for a
path, which no catch recovers with and which the habit wrote there to
read a fact of the error: it is refused after `!|` as after `|`, the
fact read by `get`, `!| get /nearest`. A question mark after a segment
of a path, the habit of a read that may miss, is refused by the parser,
which names `query`, `get /age?` read as `query /age`. A name the reader
declared is a word, and calling it stays a step [D223].

A path is a value of the kind `::path`, written `/data/users/3/email`:
a key or a place from zero at each segment, a negative place counted
from the end, a key that is a keyword with a path after a colon,
`/:a/b`, and a key that is no bare name in quotes, `/"first name"`.
It prints as it is written and reads back as itself, JSON writes its
literal as a string, two paths are equal when their segments are, and
the one order ranks the paths after the tag names, by their segments
[D16]. A path does nothing by itself; the word that takes it reads it:

- `get /a/b` answers the value at the path and refuses a miss,
  `::path/KeyNotInMapError` with the keys near it,
  `::path/IndexOutOfBoundsError`, and `::path/SubjectNotProjectableError`
  for a value on the path that has no parts, each refusal holding the
  path it followed as `:path`;
- `query /a/b` reads alike and answers `null` where a key or a place is
  missing or `null` stands on the path, and refuses another kind on the
  path as `get` does; the default it takes as its second input is a value
  it holds and never runs, answered where the path misses, while a
  `null` that stands at the path is answered as it stands, `[] | query
  /0 7` answering `7` and `[null] | query /0 7` answering `null`, the
  reading `at` gave its defaults [D166];
- `has /a/b` answers whether `get` reads the path, beside the membership
  `has` answers for any other value;
- `get` and `query` take a key, a keyword, a string or a whole number,
  as the path of one segment, so a key the query computes is read;
- over a template, a literal of paths and quotes at any depth of its
  vectors, maps and sets, `get` and `query` answer the template with
  each path read and each quote run against the subject in its place,
  any other value of it as it is [D279], `get [/price /qty]` the pair
  and `get {:who /first :n ~(get /tags | count)}` the map, and a value
  goes under a tag after the read, `get {:w /w} | tag ::Box`;
- a word whose input takes code takes a path as the code that reads it
  from each value it runs on, as `get` reads it: `map /name`,
  `filter /active`, `sort /age`, `groupBy /status`;
- an input that takes a path, the inputs of `get`, `query` and `has`
  and those of the words that combine several values of one subject,
  `sumOf`, `subOf`, `mulOf`, `divOf` and `unionOf`, takes it and reads
  it, `{:price 4 :qty 3} | mulOf /price /qty` answering `12`; any other
  input refuses a path, its refusal naming the read as `:read`,
  `~(mul (get /qty))`.

A path answers the words of `::path` alone, so a word of a vector or a
map called on one is refused, the refusal naming the read the step was
likely meant for as `:read`, `~(get /tags | count)`. A quote whose code is a path
alone answers the path, which a word that runs code never wants of a
quote it is given, so it is refused where it is written, `~(/age)` and
`~/age`, the path given bare in its place; one built, by `parse` or by
`tag ::quote`, prints under its tag, `::quote[/age]`, which reads back
as it, so every value keeps a print that reads back [D30].

A keyword is a key, data that names nothing [D221], and a path holds
keys and places, so the slash means two things a path tells apart by the
colon: inside a keyword it is a letter of the one name, `get :a/b`
reading the key `:a/b`, which a path writes `/:a/b`, and in a path it
parts the segments, `get /a/b` reading `:b`
under `:a`. A word of each kind turns one into the other [D244]:
`segments` answers the keys and places of a path, `/a/0 | segments`
answering `[:a 0]`, and `toPath` reads a path from a vector of them and
from a string that writes JSON Pointer's form, its escapes read,
`"/a~1b/0" | toPath` answering `/:a/b/0`.

`it` answers the value in the pipe, and the slash alone leaves the
language: `:r it`, `get [~(it) ~(count)]`, `5 | mul it`. `paths` answers the set
of the paths at which a value holds no parts, the outline of any value,
each a path `get` reads. `ok` answers `true`, so `ok !| false` answers
whether the step before stood, the question `false !| true` asked by a
value written as a step.

An input of a word is read from its args by the place `takes` writes:
a path, `takes :addend |~~ … ~~| /0`, read strictly by the evaluator
itself, or code over the args, `~(query /0 0)` for an input with a
default and `~(it)` for the args whole [D251], [D253]. `at` leaves the language for `get`, `query` and `has`.

The first page teaches the step as a command and the path as a value in
a small group of examples, `get /data/users | filter /active | sort /age
| map /name` among them.
