# D26 · The benchmark measures what a fresh reader of the pages does with the command line, on a set a clean author wrote, each measurement under a decision

Domain. Tooling.
Overrides [QSWRK#measure].
Decided by. The maintainer, on the readings the model laid out to him.
Decision. The mission's measure is the attempt of a fresh model in the
loop. A child of the benchmark, `claude -p` from a directory of its
own, with no settings, memory or server, runs the command line on the
tasks of a set, and the screen it is handed is the pages of the
language and of the command line as the language prints them,
`[::qlang ::cli] | map ~(get [~(it) ~(doc)])`: the page of the command line tells
what a call reads and writes, which every call of the child meets, and
links the rest, which the child follows at need. A set is written by a
clean author who never sees the language, the inputs, the tasks and a
script that computes the answers; a task with no input tells the child
that nothing is piped, and its query writes the data the task gives as
a literal. A set measures once: reading what its children missed,
`misses` or `frictions`, marks it seen, a seen set serves the work, and
the next measurement orders a new set. A measurement belongs to a
decision and carries its number, its runs named
`D<n>~cli~<model>~<k>`. The numbers of the measured decisions grow:
`run` refuses a number below the last one any set measured, and where
the change to measure spans several decisions, a decision of its own is
written for the measurement, what it measures and why. A decision is
measured once, and a second measurement under the same number states
its reason. A run fixes its circumstances when it runs: the screen it
read, printed by the tree it runs and saved under the number with its
hash, the commit of a tree with no change outside the commit, the model,
the date and the set, every call of the command line and what the
language answered; and its score, each final query run by that tree
against the answer the author computed. A report reads the scores its
runs fixed and computes nothing again; a later tree regrades an earlier
run only as a view of its own. The references of the tasks of
`scripts/benchmark/tasks.mjs`, the reading test of the first screen,
the shortest query the tree answers each with, run in the gate,
`check:benchmark`, so a task
stays solvable and its price is on record. The tooling is
`scripts/benchmark.mjs`, with `author`, `run`, `grade`, `misses` and
`frictions`, and the sets live under `scripts/benchmark/sets/` with
their runs.

mode and the shell, and a proxy of the token bill of the shortest
reading path, run on every branch, which the model wrote on 22 and 23

prediction of conformance cases.

measured one and a second measurement without a reason, and every run

a run fixes is what the tree prints for

tasks answer them in the gate.
