# D263 · Open: a value that stands for a world

Domain. Language.
Question. The maintainer asked whether a host needs a value that wraps
another, prints what it wraps and keeps the behaviour of a long-lived
thing across the steps of a query: «можно ли (и нужно ли.. и вообще
полезно ли) сделать такоую proxy сущность для нужд хостов например..
которая оборачивает какое-то значение, не имеет собственной printValue
(своей формы) и печатает то что заворачивает, но добавляет/меняет
поведение .. по типу у нас есть большое значение (состояние игры) мы
взаимоействуей им через посылку команд | left | right | jump и так
далее» (maintainer, 2026-09-28 06:09, session d427ce7e), and then «в
хостовой среде мы как бы просто не печатаем ::host-тэг верхнего уровня
.. и его сущности могут печататься компактно, а обратный резолв из
печатной формы в хостовую (это отвественность самого хоста) […] это я
просто думаю как моделировать эффекты и т.п. дела потом» (06:18). The
tree holds most of it: a tag over the state is the wrapper, a verb that
returns its subject's kind keeps it, the tag's constructor runs again
after every such verb [D41], and the `print` the kind answers is the
screen [D96]. Two things it lacks: what the screen of a world is, which
drops what the world holds and so is no literal that reads back, and the
line between a value and a reference: a value reads back as itself,
while a reference, a type of the sister project or a world, reads back
as the current state of what it names, as a URL does. The first real
test is the schemas of the sister project's entities, more complex than
the kinds of the core.
Source. The maintainer's question the text quotes; the audit held it in
its open chapter from 28 September 2026.
Alternatives. The screen an elision [D21], or the view apart from the
literal that [D96] set aside; and a tag that says whether its value is a
value or a reference, or none, a reference a host resolves on its own.
