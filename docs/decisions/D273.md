# D273 · Open: the roles of a document's declarations, read by the tools from the run

Domain. Tooling.
Question. The runtime reads the role of a declaration from its value, a
kind a value of `::kind`, a word a function under a label [D253], and
the tools read it from the form of the source: `builtFrom` and
`declaresKind` in `core/src/walk.mjs` take a body that opens with
`::kind` for a kind, which the grammar reads too, and `bodyRuns` in
`lsp/src/features.mjs` takes a body that opens with `::fn` and holds a
step named `impl` for a word. A kind built elsewhere and bound by name
is a kind to the runtime and none to the walk:

```qlang
> :K (::kind | wraps |~~ x ~~| ::map) | :Box |~~ A box. ~~| K | get [~(::Box{:a 1} | type) ~(::Box#5 !| type) ~(kinds | has ::Box)]
[::Box ::Box/PayloadKindNotTakenError true]
```

Source. The review of the branch `the-path-is-a-value`, its fourth
finding, `docs/research/reviews/2026-10-13-the-path-is-a-value.md`.
Alternatives. The language server reads the roles from the records a
session's run of the document writes, `isLabel` and `isWord` over its
scope, at the cost of running a document the reader is editing, which a
failure part of the way stops, and `builtFrom` and `declaresKind` leave
the walk and the package's surface; the grammar keeps the reading of the
form it needs to tell whether a step can call a name, which no run
precedes; or the tools keep the form and the language says a role is the
form its declaration writes, which [D253] set aside.
