# D277 · An outside audit is run by one command

Domain. Process.
Overrides [QSWRK#review].
Decided by. The maintainer: the outside audit run by one command written
where a session finds it, so no session works out again how to run it.
The model's: the script, `scripts/outside-audit.mjs`, its flags those
every outside audit ran with, the report named by its date and its tree
and opened by a line that says how it was made, and a tree with changes
no commit holds refused, since the report names the tree it read.
Decision. `node scripts/outside-audit.mjs` runs the outside audit: a
clean Opus started by `claude -p` from an empty directory of its own,
with no CLAUDE.md, no memory and no MCP server, reads the tree at HEAD,
runs `qlang` and answers `docs/research/outside-audit/prompt.txt`, and
its answer is written as `docs/research/outside-audit/<date>-<tree>.md`
under a comment that says how it was made, the environment of its run
the one a child of the benchmark runs in, without the `FORCE_COLOR` of
the session. The session writes its reading beside it,
`<date>-<tree>-reading.md`, and the fate of each finding in the README
of the audits. The instruction file names the command where it names
the outside review.
Source. «гдето надо вписать как сторонний аудит запускать просто .. или скрипт какой-то... что б проще было, найди пока как это лучше организовать что б не выяснять как каждый раз как его пускать»
(maintainer, 2026-10-13 16:54, session d65e4c1d), after the session had
found the command of the audit before in its transcript again.
Set aside. The command kept as a line of the instruction file, which a
session copies by hand and a change of its flags leaves stale; and a
word of the command line of qlang, which would bring a concern of the
work into the catalog of a host.
