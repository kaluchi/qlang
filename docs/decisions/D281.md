# D281 · Open: the scope a word of the host reads, the tree of the query or its step's own

Domain. Language.
Question. A word of the host that reads the state of its call reads the
tree of the query wherever it is called [D200]: in the body of a word
written in the language, `doc`, `binding` and `env` read the names of the
query that called the word, and the names the body declares stay out of
that tree. So a body cannot read the page of a label it declares, while
held code, whose declarations are its own scope [D278], reads its own:

```qlang
> :vec/w ~(:Box |~~ A box. ~~| | ::Box | doc | content) | [1] | w !| type
::any/doc/UnknownNameError

> :f ~(:Box |~~ A box. ~~| | ::Box | doc | content) | 1 | apply f
" A box. "
```

The state a word of the host reads carries beside the tree of the query
the scope of its own step [D278], which `open` closes held code in, so
either reading is at hand in the runtime.
Source. The lane of held code [D278], which gave a step its own scope
beside the tree of the query and so named what the rule of [D200] leaves
to ask; the maintainer decided [D200], and the choice is his.
Alternatives. A word of the host reads its step's own scope, as a body's
own steps do, so the tree of the query, its key in the scope and the
bookkeeping that keeps a body's names out of it leave, at the cost of a
word of the host called in a body no longer reading the reader's names
there; or the tree of the query stays the one a word of the host reads,
and a body names a label it declares by a word of its own.
