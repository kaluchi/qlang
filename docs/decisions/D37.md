# D37 · A host's setting is the first value of the pipe

Domain. Host.
Decided by. The maintainer: a host's setting the first value of its
pipe. The model's: the default subject, and the reading of standard input
by whether the query reads its subject.
Decision. A host sets up a query by one thing, the value its pipe
starts from, and by nothing else in the environment. `jdt q 'status'`
is `qlang '::m8 | status'`, the workspace derived from the working
directory, or `::jdt` when none is. The command line of the language
starts from the standard input when the query reads its subject and the
input carries bytes, and otherwise from `::qlang`, the noun of the
language; the empty start as `null` goes. It reads standard input only
for a query that reads its subject: a query whose first step that
declares nothing is a literal, a quote among them [D279], `1 | add 1`,
`::vec | doc`, `[1 2] | sum`, runs at once, and `in` reads standard input
when it is called; `readsItsSubject` tells it from the parser's tree, a
node it does not name counting as one that reads. A query that reads its
subject reads standard input to its end, as every reader of a pipe does:
a slow producer, `curl` over a network, is waited for, and no time
decides that an input is empty, so where a shell hands an open pipe
nothing writes to, such a query waits as `jq` and `awk` do, and
`< /dev/null` ends the wait. A host ships its sources, each
`{ uri, source, impls }`, which declare its nouns into the root beside
the language's [D153], and its command starts from its noun.
Source. «если поступать так, то все вроде как связно выходит»
(maintainer, 2026-09-23 16:32, session 86982eb5), answering the model's
sentence that a host's setting comes down to the first value of the
pipe; the default subject, the model, the same day. The assessment of
the command line as the children of the benchmark met it:
`qlang '1 | add 1'` with no input waited until the shell's timeout, and
the rules of the runs told every child to pass `< /dev/null`, which hid
the wait from the measurement. In session 22b934f8 the shell of Claude
Code handed every command a pipe, which `fstat` does not tell from
`sleep 10 | qlang`, and a read of it ended at some calls and never at
others, so nothing read from standard input tells an empty input from a
slow one; a query that reads no subject needs no input at all, as an
`awk` program of `BEGIN` alone reads none. The maintainer, on the open
questions written to the audit: «не надо
ничего откладывать ... открытые вопросы (stdin, на что высаживаем
модель) — в аудит,» (maintainer, 2026-10-11 20:17, session 22b934f8)
and «сразу решай все по пути» (20:17).
Set aside. Seeds a host installs into the environment before the query,
which is the long pipeline this replaces; `null` as the start, which
carries no meaning where a noun can. The noun of the nearest `.qlang/`
folder as the start, and a registry of the user's through which the
language's command line and the language server found the modules
installed outside a repository, the model's reading of the same day,
which no host built: a host declares its sources into the root itself
[D153], and the language's command line reads the language and its own.
An input that sends no byte within a short time read as empty, which
reads a slow producer as no input and answers a query over nothing, a
wrong answer with no sign of it; the same only where the host is told a
model reads, which keeps that wrong answer for the model; a character
device read as nothing piped, which the pipe of the shell is not.
Requirements. `readsItsSubject` answers false for each literal, a path
and a quote among them, a group whose code reads none and a
declaration before such a step, and true for a call, a group whose
code reads, a declaration whose body reads and a query of declarations
alone; the command line answers a query that reads no subject over a
standard input that never ends, `in` reads it when called, and a query
that does not parse is refused without reading it.
