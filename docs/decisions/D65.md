# D65 · A comparison is declared on each kind it compares

Domain. Language.
Decision. The ordering predicates, `gt`, `gte`, `lt` and `lte`, are
declared on each kind whose values they compare, the number, the
string, the keyword and the tag name, each with a head of its own under
one contract [D34]: a value of another kind in the slot is refused by
the head, `1 | gt "x"` answering `::number/gt/value/NotNumberError`, and
a subject of a kind no comparison is declared on finds no word,
`[1] | gt 1` answering `::call/KindAnswersNoVerbError`. The one order
ranks any two values where the language orders, `sort`, `min`, `max`
and the set [D16], and a comparison answers between two values of one
kind alone, `"b" | gt "a"` answering `true`.
Source. «по видам, числам и строкам отдельно  - ок ..» (maintainer,
2026-09-25 16:42, session 86982eb5), answering the model's question
whether `gt` stays on the kinds it compares or ranks any two values by
the one order, asked from `::number/gt | spec | /subject` answering
`:number` while `"a" | gt "b"` answers `false` and the page of `gt`
asks for “comparable scalars of the same type”
(`core/lib/qlang/operand/predicate.qlang`). The four kinds are those
`checkComparable` admitted (`core/src/ordering.mjs`), the keyword and
the tag name beside the two the question named, the model's reading of
«по видам»; the refusals the implementation raised,
`::GtOperandsNotComparableError` and its kin, left with it once the
heads refused.
Set aside. `gt` on `::qlang/any`, ranking any two values by the one
order as jq compares any two JSON values, under which `1 | gt "x"`
answers `false` without a word where comparing a number with a string
is most often a field of the wrong kind. `gt` on numbers alone, the
declaration of the time, which refuses the comparison of strings the page
of `gt` documents.
