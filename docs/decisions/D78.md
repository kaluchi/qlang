# D78 · The conversions and the code as data reside on their nouns, and every tagged value reaches the verbs of `::tagged`

Domain. Language.
Decision. `keyword` resides on `::string` and on `::keyword`, and
`parse` on `::string` and on `::quote`, declared in the module of that
noun, `qlang/quote`, each under its contract on `::qlang/any` [D62],
[D72]; `apply` resides on `::qlang/any`, its code a slot of kind code.
`payload` and `within` reside on `::tagged`, the kind of every value
under a tag, declared in `qlang/tagged`: the walk of a tagged value
reaches `::tagged` after the value's own tag and before its payload
[D34], and the head of a verb on `::tagged` takes such a value whole, a
set, a quote and a verb among them. `within` returns `/`, so the answer
of its edit mints back under the subject's tag through the tag's
constructor [D41], [D67]. The refusals of a subject of another kind
that `keyword` and `parse` raised leave, the contract answering in
their place. A verb run as code runs under the name of its slot, so
every call of a verb names the verb [D67].
Source. The maintainer handed the milestone to the model without a round
of questions: «делай автономно, я потом гляну ревью .. не переспрашивай»
(maintainer, 2026-09-25 21:09, session 86982eb5). The readings are the
model's, made while it moved the conversions of kinds and the code as
data onto their nouns by D72, where the subject of `payload` and of
`within` is a tagged value of any tag, which no kind of the walk named.
Set aside. `payload` and `within` on `::qlang/any` with an
implementation that refuses a value under no tag, a declaration the
runtime would not execute. `within` minting the edit itself, which
repeats what `:returns /` says. `tag` moved in the same branch, whose
constructor through the tag's binding needs the environment a plain
function over values does not receive.
