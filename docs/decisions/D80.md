# D80 · A host declares its operands as verbs and hands their primitives beside the source

Domain. Host.
Decision. A host's module declares each of its operands as a verb, its
head the declaration the runtime executes and its body a `::builtin`
step, and the host's locator hands, beside the source, `impls`: for each
name, a plain function over the values the head checked, the subject
first and the slots in their order [D4], [D72]. The loader records each
function beside the verb of its name, which calls it once its head has
checked the call, and refuses an implementation handed for a name the
source declares as no verb with `::UseImplNamesNoVerbError`. A verb of a
host resides on no noun: it is a binding of the scope the module's `use`
brings in, read by its keyword, `:@type | spec`, and its refusals are
the ones its site declares at each place of its head, as a built-in's
are [D74]. The dispatch wrappers `valueOp`, `nullaryOp`,
`overloadedOp` and `stateOp` leave with the operands of the hosts that
were built on them, and the core no longer exports its dispatch module;
the wrapper of the loader stays [D79]. The command line and the sister
project land the interface in the same move.
Source. The maintainer handed the milestone to the model without a round
of questions: «делай автономно, я потом гляну ревью .. не переспрашивай»
(maintainer, 2026-09-25 21:09, session 86982eb5), and the interface of
hosts was settled by D4 as `{ source, impls }`. The readings are the
model's, made while it moved the operands of the command line and of the
sister project onto verbs.
Set aside. A host's verb residing on the kinds its subject names, which
the module of a host cannot be for a noun of the core; M5 gives a host
nouns of its own. An implementation handed for an undeclared name
ignored, which lets a misspelt name drop an operand in silence. The
subjects of the sister project's operands declared in their heads,
which would refuse with the head what its implementations answer as an
error value of their own.
