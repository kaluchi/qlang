# D81 · A plain comment is whitespace

Domain. Language.
Decision. A plain comment, `|~| …` to the end of its line or `|~ … ~|`,
nesting, is whitespace wherever whitespace stands: between the steps of
a pipeline, between the modifiers of a command, inside a literal and
inside a quote. A comment carries no combinator, so a pipe is written
beside it, `5 | |~ why ~| add 3`, and a line break inside a comment
ends no line [D11]. A source of whitespace alone, comments among it, is
the blank pipeline, which answers the value it is handed, as the empty
quote does, and reads as the empty quote. The parser keeps the comments
of a source on the side, beside its tree, for the tools that paint
them, and no step, quote or trail holds one. The doc forms `|~~| …` and
`|~~ … ~~|` stay the doc literal and the doc of the declaration they
stand beside [D70].
Source. The maintainer handed the milestone to the model without a round
of questions: «делай автономно, я потом гляну ревью .. не переспрашивай»
(maintainer, 2026-09-25 21:09, session 86982eb5). The audit names the
repair: comments trivia at the level of whitespace, the doc form the
literal of documentation, and only the plain forms whitespace. The
readings are the model's, made while it rewrote the grammar.
Set aside. A comment that still stands for the pipe its leading `|`
draws, which keeps the four productions of absorption the repair
removes. A blank source refused, under which a source of comments alone,
which answered its value, would stop parsing.
