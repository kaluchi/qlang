# D87 · An argument hands an error on, and a container holds one

Domain. Language.
Decision. The places declared for any value that keep the error of a
fork [D13] are the elements of a container: the elements and entries of
a literal and the results of `*`, where an error waits as the value it
is [D85]. An argument of a step is no such place, since a step takes no
error in [D86]: a modifier that answers an error answers the call,
whatever the kind of its slot, `::any` among them [D68], and a key that
answers an error answers the operand that runs it, `sort` as `groupBy`
and `indexBy` do, so a key that misses its field is refused where it is
read. An operand whose alternatives are pipeline slots, `coalesce` and
its kin, keeps its contract, an error answer being no value [D13], and
`sort` without a key still ranks errors in the one order [D16].
Source. «если ты действительно чувствуешь что это все не костыль - то
ок... сортировка по отсуствующему ключу это по идее это ошибка там с
каким-то трейлом нашим новым или типа того.. удивлять не будет никого по
идее если вылетит ::ProjectionKeyNotInMapError» (maintainer, 2026-09-26
10:55, session 86982eb5), on the model's reading that an argument of a
step is no container, the maintainer's own of a tag: «но уж точно
базовый тэг не может получить в аргументы ошибку - та вылетит из него и
в трейл залетит» (maintainer, 2026-09-26 09:33, session 86982eb5).
Set aside. A slot of `::any` that keeps an error, under which
`[1] | append (!{:k 1})` would answer `[1 !{:k 1}]` and bodies and
primitives would meet an error no `!|` opened. The key of `sort` ranked
as a value when it answers an error, under which a misspelled key sorts
its element among the errors without a word.
