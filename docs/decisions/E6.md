# E6 · The instrument runs on a released qlang, the subject on the checkout

Domain. Process.
Decision. qlang takes two places in its own development. As the subject
it is the checkout: the conformance suite, the probes and the catalog
run the core and the command line of the tree, since what they check is
the tree. As the instrument it is whatever the process writes in qlang,
the modules of the work with their sensors and their screen [E1], [E2],
and what a session sends through them to another agent; the instrument
runs on a released version of the command line, pinned where the
work's module is declared, and never on the tree it works on, so a
branch that breaks the parser blinds none of the gates and cuts no
channel, and a branch reaches its own review through no tool [D59]. The
two go by different names, the released `qlang` for the instrument and
`node cli/src/bin.mjs` of the checkout for the subject, so a session
knows which of them answered it, and the instrument moves to a new
release at a milestone, one version behind the tree. The gates written
in JavaScript over git, the listing of requirements and the diff of the
gates, need neither.
Source. «тут у нас проблема курицы и яйца тоже есть .. если мы
разрабатываем сам qlang или там его используем для работы» with the
example of a message to another agent, «#agent("007") post "Забыл ещё
сказать, нужно ещё вот это.. добавь там в список"», and «то
разрабатывать qlang через локальный qlang может быть проблематично(ну
или это надо учитывать, что всяких байосов не было и что б агент
понимал что есть что когда сам qlang это депенденси процесса разработки
qlang)» (maintainer, 2026-09-25 04:42, session 86982eb5); «да, разнеси»
(04:51). The two places, the pinned release and the names, the model,
the same night: a tool built in the language it builds is bootstrapped
the way a compiler that compiles itself is, from its previous release,
and on that night the `qlang` of the maintainer's PATH was a link to the
checkout, so the instrument and the subject were one program.
Set aside. The instrument on the checkout, the state of that night,
under which a branch that breaks the parser silences the screen and the
channels at once, and a branch's changes reach the tools that review
it. A second checkout kept for the instrument, which asks the
maintainer to keep a tree current by hand where a release pins itself.
Replaces in part [E2], whose screen is composed in the qlang of a
release.
