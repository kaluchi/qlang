# D119 · A name has one page, and a keyword is an anchor within it

Domain. Language.
Decision. `doc` answers the page of a name, one doc, where `docs`
answered the vector of the docs of its slot, one in every declaration
of the catalog; the docs a declaration writes are the parts of that one
page. An absolute name, `::vec`, `::qlang`, `::vec/sort`, is the
subject, and a keyword is an anchor within it, as a key within a map
and a name within a scope: `::qlang | doc :pipeline` answers the page of
the member `pipeline` of `::qlang`, `::vec | doc :take` the page of a
word, a vector of keywords is a path of anchors, `::vec | doc [:take
:count]` the page of an input of a word, and a set of keywords answers
the pages of several, `::qlang | doc #[:pipeline :errors]`. A link names
a page by an address, `::link~(::qlang/pipeline | doc)`. A name declared
without a page answers null, and an anchor that names nothing is
refused.
The frame of it: the names are a space of addresses, and a verb such as
`doc`, `source` or `binding` passes from an address along one of its
axes, as a path of a file system reaches a file; an
address holds no one entity, but a set of values associated with it,
and each verb of passage reads one of them. What the address is, the
verb, and what it reaches are all values, so the pipeline goes on from
what an axis reaches as from any value, and a user who tags a value and
declares verbs on the tag adds axes of their own to the space: the jumps
of the hypertext are these passages. An explanation names its page
`page`, where it named it `doc`, because a verb a noun declares is the
one a tag name of that noun calls, and `::explanation | doc` must reach
the page of the kind.
