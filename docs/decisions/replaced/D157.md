# D157 · The core hands its implementations as a host does

Domain. Language.
Decided by. The model, at the maintainer's word to try it.
Decision. A word or a kind of the core whose chain ends in
`impl ::builtin{}`, or a name under a label whose value is
`::builtin{}`, runs the implementation the host handed for its address, and the
core is such a host of its own sources: each runtime module binds an
implementation under the addresses it serves, `number/add`, several for
one shared, `vec/has` and `vec/contains` among the five of `has`, and a
kind's constructor under its address, `vec/construct`; each source of
the language, `qlang/<noun>`, is handed those under its noun [D114].
The step names nothing: the handles `qlang/prim/<name>` and
`qlang/type/<name>` leave, with the `:impl` of a descriptor, and the
site of a verb's refusal is the last name of its address. The root
refuses a built-in the host handed nothing for and an implementation
handed for any other name, the core's sources and a host's alike
[D153].
Source. The maintainer read a page of the catalog,
`::verb~(:returns ::string | ::builtin{:impl :qlang/prim/docContent})`
in `core/lib/qlang/doc.qlang`, after the model named the handle a
second name of the verb, carrying the prefix [D153] took from the
language and differing from the address at `docContent`, `has` and
`quoteOpen`, while the command line and the sister project already
handed theirs by address: «типа можно положиться на имена из qlang и
не пролодить свои в builtin ?» (2026-10-08 16:50, session 22b934f8)
and «ок, пробуй сделать» (16:52).
Set aside. A handle kept beside the address for the primitives a name
does not reach, which no verb of the catalog needs. One table handed
to every source with the root checking it as a whole, which leaves a
host's misspelled implementation unrefused until the last source.
Pruned of what [D251], [D252] took.
Merged into [D72].

probe it names reads there, `git show f19bb249:<path>`, not in today's.
