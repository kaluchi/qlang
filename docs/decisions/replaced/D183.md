# D183 · A measurement belongs to a decision, the numbers of the measured decisions grow, and a run fixes what it read and what it scored

Domain. Tooling.
Decided by. The maintainer.
Decision. A measurement of the benchmark belongs to a decision and
carries its number: its runs are named `D<n>~<mode>~<model>~<k>`. The
numbers of the measured decisions grow: a measurement takes the number
of the newest decision, and `run` refuses a number below the last one
any set measured, so no run of an earlier decision appears after work
on a later one. Where the change to measure spans several decisions, a
decision of its own is written for the measurement: the decisions whose
changes it measures, what they touched, the first screen, the catalog or
the documents, and why the measurement is needed, to fix the result and
watch for a regression. A decision is measured once; a second
measurement under the same number states its reason, which its records
keep. A run fixes its circumstances when it runs: the screen it read,
printed by the tree it runs and saved under the number with its hash,
the commit of a tree with no change outside the commit, the model that
answered, the date, the mode and the set; and its score, each final
query run by that tree against the answer the author computed, the task,
the query, what it answered and whether it was solved. A report reads
the scores its runs fixed and computes nothing again; a later tree
regrades an earlier run only as a view of its own.
