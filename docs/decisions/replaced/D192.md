# D192 · A failure written as JSON holds its facts under `facts`

Domain. Command line.
Decided by. The model, within the maintainer's leave on the findings of
the outside audits, keeping his rule of [D103].
Decision. A failure written as JSON holds its facts under `facts`, the
word the language has for them, where it wrote `descriptor`, a word of
the runtime: `{"$error": {"$tag": …, "facts": {…}}}`.
Source. The second outside audit, at 68af9ab5: the command line breaks
the exploration of data the first page prescribes, `| type`, `keys |
first | type`, `doc` and `manifest` all refused on a JSON input, and the
reader sees the inner name `descriptor`; the maintainer's leave on what
the audits found beyond the trap of the kinds' names, «остальное реши
сам, ты лучше меня проект знаешь» (maintainer, 2026-10-11 01:43,
session 22b934f8), and his rule that a JSON input expects JSON back,
«если вычисленное qlang значение непредставимо в json (на вход ведь его
передали .. а занчит и ждут на выходе тоже json) - то ответ ошибка»
(2026-09-28 07:08, session d427ce7e), which the decision keeps.
Set aside. The answer written as its literal when JSON has no form for
it, or a flag that chooses the form of the output, as the audit
proposed: a consumer that piped JSON in reads JSON out, and an answer it
cannot parse breaks it where a refusal it can read does not.

kind alone.

codec hold, since a query of the suite writes no failure as JSON.
