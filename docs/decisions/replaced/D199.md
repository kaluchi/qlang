# D199 · The command line reads back a query the shell turned into a path

Domain. Command line.
Decided by. The model, at the maintainer's word on what the children of
the benchmark stumbled on and on the goals it chooses itself.
Decision. Under MSYS, the shell beneath Git Bash, whose `MSYSTEM` names
it, a query that begins with a drive and a slash and with the root of
the shell, the nearest directory of its path that holds the runtime
`usr/bin/msys-2.0.dll`, is read from the slash after that root:
`qlang '/data/users | segments'` arrives as `C:/Program
Files/Git/data/users | segments` and runs as `/data/users | segments`, the initial query of the
REPL alike. No source of qlang begins with a drive and a slash, so a
query that does was written by the shell. A query the command line
cannot read back, under another shell or with no runtime on its way,
fails with the note of [D144]. The reading is the command line's, at
the boundary where the shell hands its arguments, and the core reads
no path [D187].
Source. The calls of the runs on set T with the command line, read for
it: most of their parse errors were a query the shell had turned into a
path, `C:/Program Files/Git/data/users | filter ...`, and every such
path stands in a run before [D187], whose children run with the
conversion off, `grep -c 'Program Files/Git/'
scripts/benchmark/sets/T/runs/*~cli~*.json` naming the runs. So the
reader D199 serves is one outside the benchmark: a session that queries
the tree from Git Bash, and a reader of the command line there, who
meets the parse error before the note of [D144] names its cause. [D187]
set aside a reading in the language of a path Git Bash wrote, which
would carry the shell's mistake into the core; the command line reads
the path where the shell hands it, and the core meets the query as the
reader wrote it. The maintainer's word on what the children stumbled on,
«да, давай с этим что-то сделаем .. что-то на старте добавим
переформулируем, а что-то может в языке или ещё где-то реализуем»
(maintainer, 2026-10-11 02:25, session 22b934f8), and on the goals of
the session, «потом по qlang себе ищи задачи сам» (maintainer,
2026-10-11 02:52, session 22b934f8). The review of the series placed the
paths in the runs before [D187]
(`docs/research/reviews/2026-10-11-autonomous-series.md`, the ninth
finding).
Set aside. The root read from the environment, `EXEPATH` or `SHELL`,
which name the launcher of Git for Windows and which MSYS2 sets
otherwise; asking `cygpath`, a process at every such call; and the
prompt of `node scripts/benchmark.mjs prompt`, which keeps its line on
`MSYS_NO_PATHCONV=1`, since a prompt changed between two measurements
makes them two experiments.
Replaces in part [D144], which set the reading back aside as a query
the reader did not write; the reader wrote the query that began with
`/`, and the shell wrote the path.
Requirements. A query that begins with the root of MSYS reads from the
slash after it, and any other query as it came; the tests of the
command line hold both.
Merged into [D144].
