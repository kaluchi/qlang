Domain. Language.
Decided by. The maintainer; the page as a procedure, the alert and its
excerpt, and the prose below a failure are the model's.
Decision. The page behind each refusal, which `explain` reads, says
what failed, which fact names the culprit and how the call is repaired,
and the laws under its address hold the recovery through `!|` as
runnable examples; the usual cause and the refusals a page is confused
with, which few pages tell yet, are the repair the audit names. An unresolved name names the nearest known names
[D46], and a parse error the continuations a reader could have meant.

A host shows an error as an alert: its tag and its facts in the order
the catalog declares them, the data the error carries cut to what
places the failure, while a value it answers still prints whole. The
subject of the first stop of the trail, where the failure arose, and
every other fact print within an excerpt of three hundred characters
each, cut as `elide` cuts a value, a string past the excerpt giving way
whole with its head. The subject of every later stop, which the failure
only passed, gives way whole to an `::elision` marker where the marker
prints shorter, and a value an alert already shows gives way whole the
second time. Every marker's `:read` continues the query beneath `!|`,
`!| get /trail/1/subject`, so the error stays whole in the language and
each part of it one read away. A budget asked for, `--budget=N`,
applies over the alert. The command line prints an error so in script
mode and in the REPL, and the first page says it before an answer meets
a marker.

A failure the command line writes carries the prose of the page
`explain` reads for it, the repair its refusal's page tells, its links
and snippets aside, below the literal of the failure as line comments,
`|~| …` within the width of the sources, which a reading of the literal
passes over: `{:a 1} | get /b` writes its refusal and then that a key
that may be absent is read by `query`, which answers null for it or the
default it is given. A failure whose refusal has no page is written without prose,
and the REPL prints its cells without it, its reader asking
`!| explain`.

Every failure is an answer and goes to stdout, the error at rest under
the line that says it was raised [D13]: in script mode with the exit
code 0, as every answer exits [D103], the prose of its page below, and
in the REPL as the answer of its cell, a cell that does not parse among
them, standard error left to the words that write on it, `err` and
`tap`. A query that does not
parse answers `::quote/ParseError`, and an input that does not read as
the JSON it is taken for answers as `parseJson` refuses its text,
`::string/parseJson/TextNotJsonError` under `--json` and
`::string/parseJson/NumberNotFiniteError` with the `:path` of a number
past the doubles. Standard error and a nonzero code stay for what is no
answer of a query: a defect raised past the fail track, broken code of
the runtime that fails every call run beside it alike, whose first
nonzero code rightly stops them, and a call with no query; the note on a
query the shell made a path of goes to standard error beside its
failure, since such a query never parses [D144]. The page of the command
line says so.
