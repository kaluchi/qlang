# D256 · A name declared in the code stands over a verb of its name, and a value is read where a value stands

Domain. Language.
Decided by. The model, on the maintainer's words: the pipeline that allows
no silent change of the subject, a name `with` gives that steps on no rake
where it meets a verb of its name, and a local name that shoots no verb in
the foot, which [D469] answers at the top of a query. The model: the
places a value stands at, as the parser holds them for a literal [D248],
the refusal and its name, and a label of the reader in a verb of the root.
Overrides [QSNAM#reach], [QSNAM#value], [QSNAM#owner], [QSBLD#kind],
[QSBLD#recipe], [QSCOL#reduce], [QSPTH#template]
Decision. A name declared in the code, a value a quote declares, a name
`with` gives its body, an input its call declares in a recipe and a value
a binder writes at the head of code [D468] among them, stands over a verb
of its name for the steps after it, whatever the subject, and the verb is
called by its address:

```qlang
> ::order{:id 100 :item :bigmac :count 2} | with [/count] ~(get [~(count) ~(map/count)])
[2 3]
```

The name is read where a value stands: at the head of a pipeline, where it
is the subject, after a declaration and after `!|`, or as what a verb
takes, a modifier and a part of a template among them. Written as a later
step, a name that holds a value would drop the subject the steps before it
answered, as a literal written there would, so it is refused as
`::call/ValueAsALaterStepError` with its `:name`, its value as `:found`
and the `:addresses` of the verbs of its name; a node of data under a noun,
read by its address, is refused there alike, and a name given modifiers is
refused as `::call/ValueTakesNoModifiersError` as before:

```qlang
> 7 | apply ~(:rest 5 | add 1 | rest) !| get [~(tag) ~(name) ~(found)]
[::call/ValueAsALaterStepError :rest 5]

> ::order{:id 100 :item :bigmac :count 2} | with [/count] ~(keys | count !| addresses)
#[::map/count ::string/count ::vec/count]
```

A label of the reader goes into a verb of the root for its tag alone: its
bare name reaches nothing there, so a verb of the root calls the verbs of
the names it writes past a label the reader named so:

```qlang
> :sum |~~ S. ~~| | {:a 1 :b 2} | sumOf /a /b
3
```

The meeting of a value and a verb, `::call/ValueMeetsVerbError`, leaves,
and with it the mark that let a name a chain declares read its value past
the verb.
Source. A friction a child of the benchmark met, a vector put under two
tags with a tag written as each step and the second tag met alone
(`git show bb1b5891:scripts/benchmark/runs/R7.json`, friction F3), and the
ninth outside audit, which found a name that holds a quote read where a
reader meant to run it, `docs/journal/research/outside-audit/D327~1.md`.

name read as a later step, is refused as the parser refuses a literal
there.
Set aside.
- The answer printed with a line comment that names the step and what it
  likely meant, the maintainer's first variant, kept to ripen: it prints at
  the top of a query alone, where since [D469] no value stands, and the
  answer of code inside a command prints nowhere.
- A hidden value that stands for the new subject and remembers the old: it
  has no literal of its own.
- The meeting kept beside the shadowing, a name refused where a verb of
  the subject answers it: a name `with` gives is a deliberate name, and the
  refusal is the rake the maintainer named.
- A label's bare name reaching nothing in the reader's code as well: a name
  that holds a doc there is a label by the value it holds, and reads it.
