# D281 · Open: what of the reader's names code reads, the body of a word, held code and a word of the host

Domain. Language.
Question. Which of the names a reader declared does code read, the body
of a word, code held as data and a word of the host alike, and how is the
rest refused? The body of a word reads the nodes and the labels of the
scope it is called in and stands outside the reader's values [QSNAM#scope];
held code reads the words, the nodes and the labels of its step and refuses
a value under its name [QSQUO#held]. A value is named in code alone, the
top of a query declaring words [D469], so each probe names it in the code
`apply` runs. The roads part five ways. A value under
a bare name is refused in a body as a name nothing declares and in held code
as withheld, while the same value under an address reaches both:

```qlang
> 5 | apply ~(:k 3; :number/f ~(k); f !| tag)
::call/UnknownNameError

> 5 | apply ~(:k 10; :q ~(add k); apply q !| get [~(tag) ~(name)])
[::call/ValueWithheldError :k]

> apply ~(:Box |~~ B ~~|; :Box/k 3; :number/f ~(Box/k); 5 | f)
3
```

By its tag, the same value is a binding the body of a word reads and held
code withholds:

```qlang
> apply ~(:x 1; :any/r ~(::x | binding | value); r)
1

> apply ~(:x 1; :q ~(::x | binding | value); apply q !| get [~(tag) ~(name)])
[::call/ValueWithheldError :x]
```

A value named as a word closes that word to held code and leaves it to the
body of a word:

```qlang
> apply ~(:count 5; :q ~([1 2] | count); apply q !| tag)
::call/ValueWithheldError

> apply ~(:count 5; :vec/w ~(count); [1 2] | w)
2
```

A label of the reader goes into a word of the root for its tag alone, its
bare name reaching nothing there, and a value of that name stays out, as
[D256] decided:

```qlang
> :sum |~~ S. ~~|; {:a 1 :b 2} | sumOf /a /b
3

> apply ~(:sum 5; {:a 1} | sumOf /a)
1
```

A quote a group hands back unchanged is held as data, so it reads no name
of the step its parentheses stand in; and a law runs as held code
[QSSLF#laws], so a law declared under a name of the reader's data reads
that name neither bare nor through its tag:

```qlang
> apply ~(:k 10; [1 2] | map (~(add k)) !| get [~(tag) ~(name)])
[::call/ValueWithheldError :k]

> apply ~(:k |~~ Answers five. ~~| 5; :k/answersFive |~~ k answers five. ~~| ::law~(k | eq 5); ::k | runLaws | first | get [/ok ~(get /error | tag)])
[false ::call/ValueWithheldError]
```

And a word of the host that reads the state of its call reads the tree of
the query wherever it is called [D200], for what it reads as data, the tag
its step writes laid and asked through the step's own scope [D483]: in the body of a word written in
the language, `doc`, `binding` and `env` read the names of the query that
called the word, and the names the body declares stay out of that tree, so
a body cannot read the page of a label it declares, while held code, whose
declarations are its own scope [D278], reads its own. The state a word of
the host reads carries the scope of its own step beside the tree of the
query, so either reading is at hand in the runtime:

```qlang
> :vec/w ~(:Box |~~ A box. ~~|; ::Box | doc | content); [1] | w !| tag
::any/doc/UnknownNameError

> apply ~(:f ~(:Box |~~ A box. ~~|; ::Box | doc | content); 1 | apply f)
"A box."
```
The language server reads the name in the body of a verb by the text, the
language by the tree where the verb is called, so the two answer apart: the
server reaches a verb declared after the last call, which the language
refuses, and misses one declared in a group around the call, which the
language reaches; the check of the chapters for [D412] asks which the hover
and the jump to a declaration answer:

```qlang
> get [~(~(:number/f ~(g); :x (5 | f); :number/g ~(1); x) | answer !| get [~(tag) ~(name)]) ~(:number/f ~(g); 5 | (:number/g ~(1); f))]
[[::call/UnknownNameError :g] 1]
```

Alternatives. The roads, each with its cost.
- One road for every code: a value of the reader withheld and refused under
  its name, `ValueWithheldError`, in held code and in a body, where no word
  of the name answers the subject, so `count` stays the word and `k` is
  withheld alike; at the cost of held code reading a word a value of its
  name shadows in the reader's own steps. Or a value withheld wherever its
  name is read, the body of a word among it; at the cost of a word of the
  root failing where a reader named a value as a word it calls, unless the
  root's words read the root alone.
- A node of data under an address withheld as a value is, only words and
  labels reaching code; at the cost of the helpers a reader keeps under a
  noun becoming inputs.
- A quote a group hands back unchanged keeping the step it was written in;
  at the cost of a rule that follows a value through a group. A law reading
  the name it stands under; at the cost of held code that reads a value by
  where it is declared. A quote declared under a name written into by `fill`
  at its declaration, a closure that prints and reads back; at the cost of
  the quote under the name no longer being the text written and of a value
  declared after it never reaching it.
- A word of the host reading its step's own scope, as a body's own steps
  do, so the tree of the query, its key in the scope and the bookkeeping
  that keeps a body's names out of it leave; at the cost of a word of the
  host called in a body no longer reading the reader's names there. Or the
  tree of the query staying the one a word of the host reads, and a body
  naming a label it declares by a word of its own.
- Or the roads as they stand.
