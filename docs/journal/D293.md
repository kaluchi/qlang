# D293 · Open: the road by which a host's primitive takes the state of its call

Domain. Host.
Question. Does the surface a host builds on hand a host's primitive the
state of its call, as the core's own primitives take it? A primitive of
the core that reads the state of its call, `doc`, `env`, `get`, `apply`
and their kin, takes it after the values of its inputs [QSHST#source],
marked so by the runtime as it registers it, while a primitive a host
hands beside its source takes the values alone, the package exporting no
mark of a reader of the state:

```sh
$ node --input-type=module -e "const core = await import('./core/src/index.mjs'); console.log(['readingState', 'registerStateReader'].filter(name => name in core).length)"
0
```
Source. The second run of the audit [D342], on the tree 68e681c1, at the
maintainer's word «после как следаешь эти дела - можешь повторно
прогнать то же самое рецепт агент тебе оставил» (maintainer, 2026-10-16
07:15, session d7f52e95), which found the surface a host builds on; and
the consilium on the records of [D353], whose pass gave the print of
`tap` the road every primitive of the core takes, the state of its call,
`docs/journal/research/design-check/D353~1.md`.
Alternatives. The mark of a reader of the state handed to a host, a
primitive of the host taking the state of its call as a primitive of the
core does, which [D327] asks for the print of `tap` within the budget of
the host, at the cost of a host's primitive that reads the scope of its
call. Or the state left to the primitives of the core, a host's word
printing what it is handed as it is.
Pruned of what [D378] took.
