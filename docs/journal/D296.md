# D296 · Open: the tests and the guards the work keeps

Domain. Process.
Question. Which tests and guards does the work keep? The thresholds of
coverage stand at a hundred on every axis for the core and the command
line:

```sh
$ grep -A 5 "thresholds" core/vitest.config.mjs | grep -oE "(lines|functions|branches|statements): 100" | sort
branches: 100
functions: 100
lines: 100
statements: 100
```

The corpus of tests is heavier than the code it covers, and most of it
tests the mechanism: a unit test imports the internals it checks and
goes with them, while a conformance case states what the language does
and stands through any rewrite of how. The drift tests and the checks
that hold a refusal's constant to its address, a sibling's range to its
version and a document's anchors to the tree guard duplicates:

```sh
$ git ls-files --error-unmatch 'core/test/unit/*drift*'
core/test/unit/error-tag-catalog-drift.test.mjs
```
Source. The scar of a process that grows text, which the audit held,
`git show d8657d4e:docs/qlang-audit.md`, given to the journal by
[D292].
Alternatives. The threshold for the language core alone and a rule
without a number elsewhere, the conformance cases the requirements of
the language and the unit tests the scaffolding that goes with what it
scaffolds, each guard deleted with the duplicate it guards: the policy is
written into the chapter of the work and the configurations, and each
guard waits on its duplicate. The thresholds kept: the corpus grows with
the mechanism.
