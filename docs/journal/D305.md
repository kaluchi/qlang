# D305 · Open: what a name declared once counts, the step written or the step run

Domain. Language.
Question. A name is declared once in a scope, the second declaration
refused where it stands [QSNAM#scope], and a body that answers a failure
declares nothing [QSNAM#declare]. The check counts the declarations the
pipeline writes, `repeatedDeclarationsOf` in `core/src/walk.mjs`, so a
declaration the fail track skipped, or one whose body failed, still
counts, and a recovery that declares the name is refused as a second:

```qlang
> {} | raise | :x 1 !| :x 2 | x !| type
::bind/NameDeclaredTwiceError

> :x (1 | div 0) !| env | has :x
false
```
Source. The first check of the chapters, the report of names and
scope, `docs/journal/research/spec-check/2026-10-15-3d6ad533/`.
Alternatives. The step written: a declaration is counted where it is
written, run or not, as it stands, and a recovery declares another name,
at the cost of a rule the page of the refusal says in other words. The
step run: a declaration counts once it declared, so a recovery after
`!|` declares the name the failed step left undeclared, at the cost of a
refusal no reading of the text finds before the run, the language
server's among them.
