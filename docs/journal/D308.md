# D308 · Open: what a tag over a tagged payload leaves

Domain. Language.
Question. Tags stack and read from the outside in [QSLIT#tag], and an
input holds the value of its kind the walk of its tags reaches
[QSBLD#input]. The kinds of the core read a tagged payload three ways:
an input of numbers strips every tag while an input of maps keeps the
innermost, since a map under a tag is a map; `::set` reads a vector under
another tag and `::vec` refuses it, both naming `:expected #[::vec]`; and
a label laid over itself stands once only where a declaration names it:

```qlang
> :any/m (::fn | takes :x |~~ x ~~| /0 ::map | impl ~(x)) | null | get [~(m ::T{:a 1}) ~(m ::T::U{:a 1}) ~(m {:a 1})]
[::T{:a 1} ::U{:a 1} {:a 1}]

> :any/m (::fn | takes :x |~~ x ~~| /0 ::number | impl ~(x | type)) | null | get [~(m ::T#1) ~(m ::T::U#1)]
[::number ::number]

> ::Box[2 1] | tag ::set
#[1 2]

> ::Box[2 1] | tag ::vec !| get [~(type) /expected]
[::vec/PayloadKindNotTakenError #[::vec]]

> ::Lab::Lab[1]
::Lab::Lab[1]

> :Lab |~~ L. ~~| | ::Lab::Lab[1]
::Lab[1]
```
Source. The first check of the chapters, the reports of functions and
errors and of literals, order and grammar,
`docs/journal/research/spec-check/2026-10-15-3d6ad533/`.
Alternatives. A kind read beneath every tag, an input and a constructor
of the core taking the payload bare, a map and a vector as a number is,
at the cost of a recipe that no longer sees the tag of a map it was
handed. The innermost tag kept for every kind, a number under its last
tag as a map is, at the cost of the arithmetic of an input reading a
tagged number. A literal fixed by its text alone, a label laid over
itself standing twice whatever declares it, at the cost of the rule that
a label stands once over its own kind. Or the kinds as they stand.
