# D308 · Open: what a tag over a tagged payload leaves

Domain. Language.
Question. Tags stack and read from the outside in [QSLIT#tag], and an
input holds the value of its kind the walk of its tags reaches
[QSBLD#input]. The kinds of the core read a tagged payload three ways:
an input of numbers strips every tag while an input of maps keeps the
innermost, since a map under a tag is a map; `::set` reads a vector under
another tag and `::vec` refuses it, both naming `:expected #[::vec]`; and
a label laid over itself stands once only where a declaration names it:

```qlang
> :any/m (::fn | takes :x |~~ x ~~| /0 ::map | impl ~(x)) | null | get [~(m ::T{:a 1}) ~(m ::T::U{:a 1}) ~(m {:a 1})]
[::T{:a 1} ::U{:a 1} {:a 1}]

> :any/m (::fn | takes :x |~~ x ~~| /0 ::number | impl ~(x | type)) | null | get [~(m ::T#1) ~(m ::T::U#1)]
[::number ::number]

> ::Box[2 1] | tag ::set
#[1 2]

> ::Box[2 1] | tag ::vec !| get [~(type) /expected]
[::vec/PayloadKindNotTakenError #[::vec]]

> ::Lab::Lab[1]
::Lab::Lab[1]

> :Lab |~~ L. ~~| | ::Lab::Lab[1]
::Lab[1]
```

An element under a tag reads so in a fold, in `flat` and in `zip`: a map
under a tag folds as a map while a set under a tag is refused, and a
vector under a tag splices while a set under one stays whole, though the
page of `::vec/flat` splices an element whatever tag it stands under:

```qlang
> [::T{:a 1} {:b 2}] | union
{:a 1 :b 2}

> [::T#[1] #[2]] | union !| get [~(type) /index]
[::vec/union/ElementNotSetOrMapError 0]

> get [~([::T[1 2] [3]] | flat) ~([::T#[1 2] [3]] | flat)]
[[1 2 3] [::T#[1 2] 3]]
```

The constructors of the core part the same way: `::number` and `::vec`
refuse a payload under another tag, `::set` takes the vector beneath
it, and `::error` keeps the map under its tag; and a quote handed to
`apply` as its arguments is the vector of its steps:

```qlang
> get [~(::W#5 | tag ::number !| type) ~(::T[1] | tag ::vec !| type) ~(::T[2 1] | tag ::set) ~(::T{:a 1} | tag ::error | print)]
[::number/PayloadKindNotTakenError ::vec/PayloadKindNotTakenError #[1 2] "::error::T{:a 1}"]

> get [~(5 | apply (::fn | takes :x |~~ x ~~| /0 | impl ~(add x)) ~(3)) ~(5 | apply ~(add 1) ~())]
[8 6]
```

A key under a tag reads two ways as well: `toKeyword` reads the number
or the string beneath the tags, while `groupBy`, `indexBy` and `toMap`,
which file a key as `toKeyword` does, refuse it; and the payload of
`::span`, of a vector of numbers, takes a set, which orders the six
numbers again:

```qlang
> get [~(::W#1 | toKeyword) ~([::W#1] | groupBy !| type) ~([[::W#1 2]] | toMap !| type)]
[:"1" ::vec/groupBy/KeyKindNotTakenError ::vec/toMap/KeyKindNotTakenError]

> ::span#[5 4 3 2 1 0] | start
::point#[0 1 2]
```

A path reads beneath the tags over each value it meets [QSPTH#get], while
a null under a tag on the way stops `query`, which answers null where
null stands on the way [QSPTH#query]; and a key under a tag reads two
ways: `get` and `query` answer it as a template, while `has`, `put` and
`delete` read the key beneath its tags:

```qlang
> {:a ::T#null} | query /a/b !| type
::path/SubjectHasNoPartsError

> {:a null} | query /a/b
null

> {:a 1} | get [~(get ::K:a) ~(has ::K:a) ~(put ::K:a 2) ~(query ::K:a)]
[::K:a true {:a 2} ::K:a]
```

A kind that names the kinds of its payload lays its tag over the value of
those kinds beneath the tags the payload stood under, which it leaves,
while a kind that names none lays its tag before them, and the innermost
tag over a map stays where a tag over it leaves:

```qlang
> :Pos |~~ P ~~| (::kind | wraps |~~ n ~~| ::number) | ::W#5 | tag ::Pos
::Pos#5

> :Pos |~~ P ~~| | ::W#5 | tag ::Pos
::Pos::W#5

> :K |~~ K ~~| (::kind | wraps |~~ m ~~| ::map) | ::T::U{:a 1} | tag ::K
::K::U{:a 1}
```

The elements and the answers a word reads as a kind part the same way: a
string under a tag is no element `join` takes, and a boolean under a tag
is a condition `if` and a condition `allOf` computes at the call take,
while one a quote answers is refused:

```qlang
> [::T"a" "b"] | join "," !| type
::vec/join/ElementNotStringOrKeywordError

> get [~(5 | if (true | tag ::Ok) ~(1) ~(2)) ~(5 | allOf (true | tag ::Ok)) ~(5 | allOf ~(true | tag ::Ok) !| type) ~([1 2] | filter ~(gt 0 | tag ::Ok) !| type)]
[1 true ::any/allOf/ConditionNotBooleanError ::vec/filter/ConditionNotBooleanError]
```

`raise` alone of the primitives reads the tags its walk passed, by a flag
of its own, `registerReaderOfPassedTags` in `core/src/primitives.mjs`, on
which `runPrimitive` in `core/src/dispatch.mjs` hands it the passed
tags, since a tag over a map stands two ways: over a bare map in the
map's header, and over any other value holding it under the tag, which the
walk passes,
`passedTags[0] ?? sourceMap[TAG_HEADER_SYMBOL] ?? ERROR_TAG` (`raisedFrom`
in `core/src/runtime/raise.mjs`); the raise of a map under two tags keeps
the outer alone. It reads the state of its call as well, handed after the
passed tags, by which it lays the `:trace` it raises through the label of
`::trace`. The flag came with the error kept on top of its value
(9b461409).

```qlang
> get [~(::Foo{:a 1} | raise !| type) ~(::Bar::Foo{:a 1} | raise !| get [~(type) ~(keys)])]
[::Foo [::Bar #[:a :trace]]]
```
