[QSPTH#get], `query` answers null where null stands on the path
[QSPTH#query], a key alone is a keyword, a number or a string and any

A key under a tag reads two ways too: `get` and `query` answer it as a
template, while `has`, `put` and `delete` read the key beneath its tags:

```qlang

```

A path keeps the text of each segment, `makePath` in
`core/src/types.mjs`, and `segments` reads each by its look, an index where
the text reads as a whole number and a key otherwise (`path/segments` in
`core/src/runtime/path.mjs`), so the key `:"0"` given to `toPath` comes
back as the index `0`, and the two paths are one value. And a number
given to `get` is a key alone and itself inside a template, so a later
step that builds a vector of numbers by `get [1 2]`, as the page of
`::quote/StepNotCommandError` teaches (`core/lib/qlang/quote.qlang`) and
the law `:isAValueOfItsOwn` writes (`core/lib/qlang/builtin.qlang`),
answers the numbers, while `get 1` reads the index 1:

```qlang
> get [~([:a :"0"] | toPath | segments) ~([:a :"0"] | toPath | eq ([:a 0] | toPath))]
[[:a 0] true]

> [10 20 30] | get [~(get 1) ~(get [1 2]) ~(get [/1 /2])]
[20 [1 2] [20 30]]
```

`has` asks one question two ways by the kind of the subject: on a map it
asks what `get` reads, a number naming the key of its text [QSPTH#has],
while on a vector and a set it asks whether an element equal to the value
stands and reads a path, so a number asks for an element there while `get`
reads the index it names; `contains` asks a vector and a set for an element
[QSTXT#search]:

```qlang
> [5 6] | get [~(has 0) ~(has /0) ~(get 0)]
[false true 5]

> {:"0" 5} | get [~(has 0) ~(has /0) ~(get 0)]
[true true 5]

> #[5 6] | get [~(has 5) ~(has /0) ~(get 0)]
[true true 5]
```

And a refusal names the place of a part by its `:path`: a read that misses
names the path it followed, a value of `::path`, which the kind of errors
declares [QSERR#site], while `parseJson` names the place of a number past
the doubles in the text by a vector of its keys and its indices

number at the top of the text standing at the empty vector, which no path
writes [QSPTH#value]:

```qlang
> "{\"a\": {\"b c\": [1, 1e400]}}" | parseJson !| get /path
["a" "b c" 1]

> {:a {:b 1}} | get /a/c !| get /path
/a/c

> get [~(::error/path | binding | get /value) ~(::string/parseJson/NumberNotFiniteError/path | binding | get /value) ~("1e400" | parseJson !| get /path)]

```
