# D311 · Open: a comparison across kinds and `::desc`

Domain. Language.
Question. The comparisons of the core compare within one kind, a value
of another kind refused under the input [QSCND#compare], while `::desc`
owns comparisons that rank its payloads by the one order [QSORD#desc].
An input of `::number/gt` reaches the number beneath `::desc`, so a
number compares with a descending number by its payload, `::desc`
refuses a number, and the one order ranks the number first:

```qlang
> 2 | gt (1 | desc)
true

> 1 | desc | lt 2 !| type
::desc/lt/value/KindNotTakenError

> get [2 ~(1 | desc)] | sort
[2 ::desc#1]
```
Source. The first check of the chapters, the report of literals, order
and grammar, `docs/journal/research/spec-check/2026-10-15-3d6ad533/`.
Alternatives. A value under `::desc` refused by the comparisons of the
core as a value of another kind, at the cost of the walk of an input
stopping at `::desc`. Every comparison ranking by the one order, as
`sort` does, at the cost of comparisons that no longer refuse a value
of another kind. Or the comparisons as they stand.
