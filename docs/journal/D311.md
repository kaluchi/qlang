# D311 · Open: a comparison across kinds and `::desc`

Domain. Language.
Question. The comparisons of the core compare within one kind, a value
of another kind refused under the input [QSCND#compare], while `::desc`
owns comparisons that rank its payloads by the one order [QSORD#desc].
An input of `::number/gt` reaches the number beneath `::desc`, so a
number compares with a descending number by its payload, `::desc`
refuses a number, and the one order ranks the number first:

```qlang
> 2 | gt (1 | desc)
true

> 1 | desc | lt 2 !| type
::desc/lt/value/KindNotTakenError

> get [2 ~(1 | desc)] | sort
[2 ::desc#1]
```

A number under any other tag compares so too, by its payload, while the
one order ranks every number before a value under a tag:

```qlang
> get [~(2 | gt ::Box#1) ~([2 ::Box#1] | sort)]
[true [2 ::Box#1]]
```

A string compared with a number is refused under the value the call
gives, while the subject is what the reader got wrong, a record that
holds its age as text: the refusal names `18` as the value of the wrong
kind, and the repair it suggests, the value written as text, compares by
characters and answers wrong without a failure:

```qlang
> {:age "x"} | get /age | gt 18 !| get [~(type) /actualValue]
[::string/gt/value/KindNotTakenError 18]

> [{:age "5"} {:age "30"} {:age "100"}] | filter ~(get /age | gt "18")
[{:age "5"} {:age "30"}]
```

The pages of the four refusals of the comparisons of strings name the
repair of the subject, `get /age | toNumber | gt 18`.
The principles of [D332] weigh it: a refusal names the part a reader
repairs, the culprit of the pair, in the reader's terms.
