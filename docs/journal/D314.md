# D314 · Open: an error that writes an empty trail, raised again

Domain. Language.
Question. A map that writes its `:trail`, empty among them, resumes that
path when raised and adds no stop [QSERR#trail], while the error at rest
`!|` grounds it to holds no empty `:trail` [QSERR#print], and the trail
holds the steps a failure skipped [QSERR#rest]. Together they lose the
steps an error with an empty trail skips, and an error at rest raised
and caught again is itself only where it holds a trail it did not
write empty:

```qlang
> {:a 1 :trail []} | raise | count !| trail
[]

> !{:a 1 :trail []} | :e it | raise !| eq e
false

> !{:a 1} | :e it | raise !| eq e
false
```
Source. The first check of the chapters, the report of functions and
errors, `docs/journal/research/spec-check/2026-10-15-3d6ad533/`.
Alternatives. An empty trail is no trail: a raise of it starts the path
over with a stop at the raise, as a map with no `:trail` does, at the
cost of the clause that an empty trail written resumes a path. A raise
that resumes an empty trail starts its first stop at the step after it,
which the skipped steps join, at the cost of a stop no step raised. Or
the rules as they stand, the skipped steps of an empty trail lost.
