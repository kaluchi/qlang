# D335 · `--fail` gives a failure the exit code 1

Domain. Host.
Decided by. The maintainer, that the command line may take the flags the
outside audits ask for, kept complete and simple; that one flag gives a
failure its code, and that JSON a line and files stay with the language
and the shell, is the model's.
Overrides [QSHST#answer]
Decision. `--fail` before the query gives an answer that is a failure
the exit code 1, the failure written to standard output as without it,
a failure a query that wrote by `out` leaves unwritten among them; a
caught failure is a value, and every value keeps the code 0. Without the
flag every answer keeps the code 0, so calls run side by side never stop
each other:

```sh
$ qlang --fail '"x" | add 1' > /dev/null || echo failed
failed

$ qlang '"x" | add 1' > /dev/null && echo answered
answered
```

JSON a line reads by `--raw` and the language, which the usage shows,
`qlang --raw 'lines | map ~(parseJson) | filter ~(has :error)' < app.ndjson`,
and a file by the redirection of the shell, `< data.json`.
Source. The ninth outside audit,
`docs/journal/research/outside-audit/D327~1.md`, which asked for a code
a script tests, by default or by a flag, and for JSON a line and files as
arguments; the maintainer's answer to its reading, «в целом можешь
добавить и ключи -- в cli.. но вряд ли агенты захотят этим всем
пользоваться... если для полноты функционала и снятия напряжения
будуших прочтений - то можно добавить или переделать там так что б оно
было и полно и просто ...» (maintainer, 2026-10-16 02:19, session
70702c43); and the reason of the code 0, «просто у нас когда код не 0 -
то параллельный запуск башей триггерил стоп у claude code» (maintainer,
2026-10-12 03:24, session dda915a5).
Set aside. A nonzero code by default, which stops the calls a harness
runs beside the one that failed; a failure written to standard error, a
second channel the maintainer refused, «не первый аудитор.. зачем их
раскидывать по разным каналам .. что бы что? ..» (maintainer, 2026-10-12
03:22, session dda915a5); a false or null answer exiting as a failure,
as `jq -e` does, which tells a predicate from a failure no more; a code
of its own for a failure beside the 1 of a defect, which a script that
tests whether it got an answer does not need; and a flag for JSON a line
and files given as arguments, which the language and the shell compose.
Requirements. The tests of the command line: `--fail` read before the
query, a failure exiting with 1 under it and 0 without it, written to
standard output alike, a failure left unwritten by `out` exiting with 1,
and a value exiting with 0.
