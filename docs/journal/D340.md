# D340 · Open: the boundary of the core, what it carries for its tools and its hosts, and the roads an older host kept open

Domain. Implementation.
Question. Which parts of the core depend on what should depend on them,
or carry a need of a tool or a host past the embedding boundary, and which
roads of an earlier host stay open with no host on them? Is each moved,
closed or kept? Each part below names the files and the functions, shows
the fact by a probe, and tells the earlier layer where the history keeps
it; the roads with their costs stand under `Alternatives.`. The principle
weighed is the host boundary of [the aim](AIM.md#principles), the needs
of a terminal, an editor and byte-exact JSON shaping no semantics of the
core, and the fourth condition of [its state](AIM.md#state), every
consumer reading what it needs from the catalog with no spelling of the
language of its own. The pentimento audit [D342] found them; its other
records are [D338], [D339] and [D341]. Part 11 moves a
section of a chapter and its cases, so a decision writes it as a record
of the language with the sections it overrides.

Each anchor names a file and the function or the words it holds; the
tree is that of this record's commit, on the branch `the-trail-as-frames`
over the baseline e90d39b3.

**10. JSON is read by three readers, one of them exported for a host
alone.** `fromPlain` reads a JavaScript object of JSON's shape, a key that
reads as an index moved by the object, and the package exports it
(`core/src/index.mjs`) as the road a host builds a lawful answer of its
words by, which the page of the package tells and the test of its root
holds, while no module of the tree calls it and the sister project carries
copies of its own, `jsonToQlang` [D293];
`fromJsonText` reads the text of JSON in the order it writes its keys and
serves `parseJson` and the command line, which repeats the body of
`parseJson`, `JSON.parse` to tell the text and `fromJsonText` to read it
(`cli/src/stdin.mjs`); the grammar's literal of JSON is the third.

```sh
$ git grep -l -w -F fromPlain -- core/src cli lsp site | sort
core/src/index.mjs
core/src/runtime/json.mjs
```

**11. The command line keeps the flags of its first contract.** `--json`
and `--raw` came with the contract “JSON in → JSON out” of 59e63f48,
where `--json` gave the code 1 to an input that did not read. A failure is
an answer exiting with 0 [QSHST#answer], so `--json` lives by putting the
query `parseJson` in the place of the reader's own where the input does
not read (`cli/src/main.mjs`), and `--raw` does what `in` does, the text
as it came, but for a JSON text past the doubles, which the lift of the
subject refuses before `in` runs, `printf '[1e400]' | qlang 'in | count'`.
The usage is spelled by the help in `cli/src/argv.mjs`, the page `::cli`,
`cli/README.md` and [QSHST#stdin].

```sh
$ grep -c -F "unreadable ? 'parseJson' : queryText" cli/src/main.mjs
1
```
