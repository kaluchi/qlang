# D342 · Open: the audit of the earlier layers of the texts that state what holds, and its recipe for a run again

Domain. Process.
Question. Does the work keep the audit that found [D338], [D339], [D340]
and [D341] as a check of its own, run again on a later tree by a script,
as the check of the chapters is run, or by hand from the recipe below?
The recipe is the run of this audit on the baseline e90d39b3, written for
a session that never saw it: what it looks for, how it reads the tree
while another session edits it, what the main session reads, how its four
clean readers are started and with what prompt, how each finding is
checked before a record holds it, which ways of looking found the most,
what the run cost, and how a run again starts from these records.

**What it looks for.** The scars of a past the texts that state what hold
still carry [QSWRK#documents], the chapters, the pages of the catalog,
the cases, the comments and names of the code and the seeds, under six
kinds:

1. A name, a term, a word, a fact, a refusal, a path or a module that would
   not exist, or would be simpler or fewer, were the language built from a
   clean sheet for the mission of [the aim](AIM.md#mission): an identifier
   that says what its value no longer is, a word kept for the habits of an
   earlier design, two mechanisms where one serves.
2. Drift: one thing by two words, or one word over two things.
3. An outdated lexicon: the words of an earlier model, those of objects,
   builtin, operand, argument, captured, polymorphic, plain.
4. An adapter: newer code reaching older code through a conversion, a
   wrapper, a second table, a special case, a flag or an export kept for
   an older shape, one fact computed in two places.
5. Wrong subordination: a part depending on what should depend on it, the
   core holding a need of a tool or a host, a word on the wrong noun, a
   concept told by a later one.
6. A pentimento of one sentence: a history, a reason, a contrast with what
   the tree does not hold, a word to a reader.

**The tree it reads, and a clean copy for its probes.** The audit reads
the last merge of master, the baseline. Where another session edits the
working tree, every read and every search names the commit:
`git show <commit>:<path>`, written to a folder outside the repository
and read whole from there, and `git grep -n <pattern> <commit> -- <paths>`;
no reader runs the gate, a check, a script of `scripts/` or the command
line of the checkout, since a second boot of the language starves the
other session's gate. The queries run on a clean copy of the core of the
commit, which `git archive` writes outside the repository, the parser
built into it from the repository's own peggy:

```sh
git archive <commit> core | tar -x -C <copy>
node -e "const peggy = require('<repo>/node_modules/peggy'); const fs = require('fs'); const dir = process.argv[1] + '/core'; fs.mkdirSync(dir + '/gen', { recursive: true }); fs.writeFileSync(dir + '/gen/grammar.mjs', peggy.generate(fs.readFileSync(dir + '/src/grammar.peggy', 'utf8'), { output: 'source', format: 'es', trace: false, allowedStartRules: ['Query'] }))" <copy>
```

and a runner of a few lines answers each query of a file as the language
prints it, `node probe.mjs <copy> <queries>`:

```js
import { readFileSync } from 'node:fs';
const root = process.argv[2];
const { evalQuery, langRuntime, printAnswer } = await import(`file:///${root}/core/src/index.mjs`);
const env = await langRuntime();
for (const query of readFileSync(process.argv[3], 'utf8').split('\n').filter(line => line.trim() && !line.startsWith('#'))) {
  const answer = await evalQuery(query, new Map(env));
  console.log(`> ${query}\n${await printAnswer(answer, env)}\n`);
}
```

**What the main session reads.** The bootstrap of `CLAUDE.md`; then the
whole of `core/src` and every chapter of `docs/spec`, the reading no
reader is handed; the cycles of the imports of `core/src`, which a script
computes from the commit:

```js
import { execSync } from 'node:child_process';
import path from 'node:path';
const [repo, commit] = process.argv.slice(2);
const files = execSync(`git ls-tree -r --name-only ${commit} -- core/src`, { cwd: repo, encoding: 'utf8' })
  .trim().split('\n').filter(file => file.endsWith('.mjs') && !file.endsWith('parser.mjs'));
const graph = new Map(files.map(file => {
  const text = execSync(`git show ${commit}:${file}`, { cwd: repo, encoding: 'utf8', maxBuffer: 1 << 26 });
  const deps = [...text.matchAll(/(?:import|export)\s+(?:[^'";]*?\s+from\s+)?['"](\.[^'"]+)['"]/g)]
    .map(match => path.posix.normalize(path.posix.join(path.posix.dirname(file), match[1])));
  return [file, deps];
}));
let next = 0; const stack = []; const index = new Map(); const low = new Map(); const cycles = [];
const strong = node => {
  index.set(node, next); low.set(node, next); next += 1; stack.push(node);
  for (const dep of graph.get(node).filter(dep => graph.has(dep))) {
    if (!index.has(dep)) { strong(dep); low.set(node, Math.min(low.get(node), low.get(dep))); }
    else if (stack.includes(dep)) low.set(node, Math.min(low.get(node), index.get(dep)));
  }
  if (low.get(node) !== index.get(node)) return;
  const cycle = []; let member;
  do { member = stack.pop(); cycle.push(member); } while (member !== node);
  if (cycle.length > 1) cycles.push(cycle.sort());
};
for (const node of graph.keys()) if (!index.has(node)) strong(node);
for (const cycle of cycles) console.log(cycle.join(' '));
```

the words of one concept counted across the texts and the code,

Each reader is handed one prompt, its slice and its files written into
it; the scars the open records hold are written in as known, so it looks
past them:

```text
You are a read-only analyst in the repository <repo>. Your task is one
slice of a larger audit; you report findings and change nothing.

HARD RULES
- Do not modify, create or delete any file in the repository. No git
  command that changes state. Read-only git (show, grep, log, diff, blame)
  is fine.
- Do not run npm test, npm run ci, any check script, any script under
  scripts/, the qlang command line or node cli/src/bin.mjs: another session
  may run the gate, which a second boot of the language starves.
- The audit is of the commit <commit>. Read every file another session
  edits through git show <commit>:<path>, written to <folder> outside the
  repository and read whole from there; search with
  git grep -n <pattern> <commit> -- <paths>; cite the lines of <commit>.

WHAT THE AUDIT LOOKS FOR
The texts that state what holds are the cataphatic texts: the chapters of
docs/spec/, the pages of the catalog (the docs and the comments of
core/lib/qlang.qlang and core/lib/qlang/*.qlang, the names of words, facts,
refusals and laws), the conformance cases, the comments and identifiers of
the code, and the seeds (CLAUDE.md, the READMEs). They must read the same to
a session that saw none of the history. Find the scars of a long-gone past
the commit still carries:
1. Names, terms, words, facts, refusals, paths, modules, functions that
   would not exist, or would be simpler or fewer, were the language built
   from a clean sheet for its current mission: an identifier that says what
   its value no longer is; a word kept for the habits of an earlier design;
   two mechanisms where one serves.
2. Drift: one thing by two or more words, or one word over two things.
3. Outdated lexicon: the vocabulary of an earlier model (object words,
   builtin, operand, argument and the like) in names, docs, comments, test
   titles or case names.
4. Adapters: newer code reaching older code through a conversion, a
   wrapper, a second table, a special case, a flag or a re-export that
   exists only because an older shape stayed; one fact computed in two
   places.
5. Wrong subordination: a component that depends on something that should
   depend on it, a concept explained by a later one, a module of the core
   holding knowledge of a host or a tool, a word on the wrong noun.
6. Narrow pentimento sentences: a history, the justification of a change,
   a contrast with what the tree does not hold, a word to a reader.

THE CURRENT MISSION AND VISION. Read first, whole: docs/journal/AIM.md,
git show <commit>:core/lib/qlang.qlang (its vocabulary is what the language
teaches), docs/spec/README.md, and the section code of
docs/spec/QSWRK-the-work.md.

KNOWN SCARS, held by open records: <each open record, a line of what it
holds>. Report a finding that touches one only if it adds something new,
and name the record.

YOUR SLICE: <the slice, its files, and what to pay attention to>.

OUTPUT
At most 25 findings, the weightiest first. For each: where (file:line at
<commit>, with a git grep -c count where the count matters); the text (the
exact words, short); the kind (one of the six); the scar (one or two
sentences, the earlier layer and why the mission would not have it); from
scratch (one sentence); the probe (a qlang query, not run, or a git grep).
Be concrete and verifiable, say unsure where you are, no praise, no summary,
no recommendation beyond the from-scratch line.
```

**How a finding enters a record.** The main session checks each finding
before a record holds it: a query on the clean copy, or a grep at the
commit; the history of a name by `git log -S <name>` and
`git show <commit>:<path>`; the maintainer's earlier words on its axis by
`node scripts/sensors/maintainer-messages.mjs`, a choice the maintainer made
quoted with its time and session, since a removal waits for the
maintainer's words on its axis [QSWRK#journal]; and the open record that
holds a part of it named. Then the findings part: the repairs that move
no rule, [D338], from the deeper scars of the language [D339], of the
boundary of the core [D340] and of the words [D341], each item with an
anchor that names a file and the words it holds, since its line moves, and
a probe that answers now and changes with its repair; every probe is run
again on the tree of the records' commit,
`node scripts/sensors/run-probes.mjs <record>`, before the commit, and a
count goes to a command beside the text rather than into a probe, so the
gate does not fail on a word added elsewhere.

**What found the most.**

- `git log -S` of a name that reads oddly finds the layer it came from:
  `typeKeyword`, `isQSet`, `overloadedOp`, `OperandCall`.
- A table aligned on a longer name a rename shortened, and a rank written
  between two integers.
- A comment or a page that names a consumer, a tool, a release of a
  platform, or a word the catalog no longer has, `at`.
- A sentence of a page held against the probe of its own law or of a
  constructor's refusal: the page of a constructor, `tag ::map`.
- One literal of the language spelled in several modules, found by its
  text: `'::'`, `+ 2 + node.tag.length`, the loop beneath the tags.
- An export of the package that no module of the tree and no host imports.
- The words of one concept counted across the chapters, the catalog and
  the code, and the cycles of the imports.
- The names of the cases and the titles of the tests, written once and
  read by no one since.

**What the run cost.** The four readers used, in tokens and minutes: A
360,532 and about 19, B 460,770 and about 23, C 399,357 and about 19, and
D 453,546 and about 31, started at once; the main session read the core
and the chapters whole beside them, and checked the findings of each as
its report came.

**A run again** starts from the open records [D338] to [D341]: their
probes, which `check:probes` runs, tell which items stand, and the items
that stand go into the prompt as known scars, so the readers look past
them; a new finding enters the record of its kind, and a repaired item
leaves its record with its probe in the commit that repairs it.
