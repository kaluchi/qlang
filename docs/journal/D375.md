# D375 · What names a part to `get` and `query`, a number a key of its text, the place of a number in JSON, a literal after a catch, and the alternatives of `coalesce` in their place

Domain. Language.
Decided by. The model, which the maintainer handed the open records to
[D353], as the batch of the paths, the keys and the alternatives of
`coalesce`, within the maintainer's words its source quotes: that `get`
and `has` agree on a map, that `coalesce (get /t) 30` over a null `:t`
answers wrong, and that a failure is better than a null slipped in.
Overrides [QSPTH#key], [QSPTH#verbs], [QSCOL#algebra], [QSCND#coalesce],
[QSERR#catch], [QSSYN#step], [QSPRN#json]
Decision.
- `get` and `query` read a path, a key alone, a keyword, a number or a
  string, the path of one segment of its text, or a template, a vector, a
  map or a set of paths and quotes, or a value under a tag, a quote among
  them, and nothing else: a value that names no part, null, a boolean, a
  regex and a tag name, is refused under their input `path` by its kinds,
  which name no `::quote`, so a key a modifier failed to compute answers
  its failure as before [QSQUO#modifier],
  `::any/get/path/KindNotTakenError` and
  `::any/query/path/KindNotTakenError`, so a key computed from data that
  holds null or a boolean is refused at the step that reads it, where it
  answered itself.

```qlang
> {:true 1 :k null :f true} | get [~(get (get /k) !| type) ~(get (get /f) !| type)]
[::any/get/path/KindNotTakenError ::any/get/path/KindNotTakenError]

> {:a 1} | query null 7 !| get [~(type) /expected]
[::any/query/path/KindNotTakenError #[::keyword ::map ::number ::path ::string ::tagged ::vec]]

> {:a 1} | get [~(get #[/a]) ~(get ::Box[/a]) ~(get ~(get /a)) ~(get !{:x /a})]
[#[1] ::Box[1] 1 !{:x 1}]
```

- A number names the key of its text wherever a key is taken: `minus`
  takes out of a map and `inter` keeps of it the keys a map, a vector or a
  set names, each a keyword, a number or a string, an element of another
  kind refused at its index with `:expected #[::keyword ::number ::string]`,
  under the input `keys` of the verb of a map and under the fold of a
  vector; and `toPath` reads a vector of keys and indices, each a keyword,
  a string or a number, the segment of its text, as `get` reads a key
  alone, an element of another kind refused as
  `::vec/toPath/ElementNotKeyError` at its index. A path answers `toPath`
  with itself, as a kind answers its own verb [QSCND#convert].

```qlang
> {:"1" 5 :b 2} | get [~(minus [1]) ~(inter [1]) ~([{:"1" 5 :b 2} [1]] | minus)]
[{:b 2} {:"1" 5} {:b 2}]

> {:a 1} | inter [true] !| get [~(type) /index /expected]
[::map/inter/keys/ElementKindNotTakenError 0 #[::keyword ::number ::string]]

> get [~({:a 1} | minus [:a 1] !| get [~(type) /index /expected]) ~([{:a 1} [1]] | minus !| type)]
[{} {:a 1}]

> get [~([:a 1.5] | toPath) ~([:a true] | toPath !| get [~(type) /index]) ~(/a/0 | toPath) ~(::T#/a | toPath)]
[/a/"1.5" [::vec/toPath/ElementNotKeyError 1] /a/0 ::T#/a]
```

- A refusal names the place of a part by its `:path`, a value of
  `::path`, which the kind of errors declares: `parseJson` refuses a
  number past the doubles with the path to it in the text, and with none
  where the number is the whole text, which no path names [QSPTH#value];
  its label declares no `:path` of its own.

```qlang
> "{\"a\": {\"b c\": [1, 1e400]}}" | parseJson !| get /path
/a/"b c"/1

> "1e400" | parseJson !| keys
#[:trace]

> "[1e400]" | parseJson !| get [~(type) /path]
[::string/parseJson/NumberNotFiniteError /0]
```

- After `!|` a value is the recovery the catch answers, and a path and a
  literal that holds a path or a quote at any depth, the template `get`
  reads, are refused as after `|`, naming `get` over them, as
  `::fail/StepNotCommandError` where the step is built from data; a
  literal that holds neither stands as the recovery.

```qlang
> "!{:k 1 :j 2} | raise !| [/k /j]" | parse !| get /message
"a literal that holds a path or a quote is the template `get` reads: write `get [/k /j]`"

> get [~(!{:k 1} | raise !| [1 2]) ~(::fail~([/k]) !| type)]
[[1 2] ::fail/StepNotCommandError]
```

- `coalesce` answers the first of its alternatives that answers a value,
  each in its place: code, a quote or a path, runs against the subject,
  and a value answers itself; the subject stands before the alternatives
  only where the call gives one alternative and it is a value,
  `coalesce 30` reading the subject, else 30. An alternative passes to the
  next where it answers null or the refusal of a read `query` answers null
  for, a key a map lacks, an index past an end or null on the way,
  `::path/KeyNotInMapError`, `::path/IndexOutOfBoundsError` and
  `::path/SubjectHasNoPartsError` over null, wherever its code read it;
  code that answers any other failure answers the call with it, and null
  answers where every alternative passes.

```qlang
> {:t null} | coalesce (get /t) 30
30

> get [~({} | coalesce ~(nosuchword) 30 !| type) ~({} | coalesce ~(1 | div 0) ~(2) !| type) ~({:a 5} | coalesce /a/b 0 !| type)]
[::call/UnknownNameError ::number/div/divisor/ZeroError ::path/SubjectHasNoPartsError]

> get [~({:a null} | coalesce /a/b 0) ~({} | coalesce ~(get /a | add 1) 0) ~(5 | coalesce 30) ~(null | coalesce 30)]
[0 0 5 30]
```

- `has` asks a map whether `get` reads the key it is given, and a vector
  and a set whether they hold an element equal to it [QSPTH#has]; a
  segment of a path is text, `/"0"` the path `/0` [QSPTH#value]; and a
  number alone is a key where in a template it is the value it writes
  [QSPTH#key]: these stand as the chapters state them.
- The words of one subject, which refuse a part their paths read under
  the word their recipe calls, are the question of [D294], and a null and
  a key under a tag, which `query`, `get`, `has` and the verbs that write
  read two ways, the question of [D308], each carried by its batch
  [D353].

Set aside.
- A key computed at the call that is no keyword, number or string refused
  under the input of the strict read: a template a call computes or a
  name holds is read in that place [QSPTH#template], which the kinds of
  the input keep. A value that names no part answered as the template it
  is: a key a call computed as null answered itself in silence.
- `has` asking what `get` reads on every kind, `[5 6] | has 0` answering
  true: a set holds no index a reader means, and `[5 6] | has 5` would
  answer false where a reader asks for the element, as the `has` of a set
  in JavaScript does, the `has` of a map there asking for its key.
- A path holding a key and an index apart, `:"0"` a key and `0` an index:
  a segment is the text JSON Pointer writes, and one path is written one
  way. A number in a template read as an index: a template writes a
  literal, `get [1 2]`.
- The `:path` of `parseJson` a vector of keys and indices: a second kind
  for the one fact the kind of errors declares; or a fact of its own name,
  `:at`: a second fact for one place.
- For `coalesce`, a path read softly beside code read strictly: code could
  not fall back where the part it reads is missing, and a path would be
  read two ways by one verb. Every failure taken as no value: a name
  misspelled and a refusal of the reader's own code answered in silence.
  The subject first wherever every alternative is a value: a group that
  read null put the subject before an alternative written as the
  fallback. The subject first only through `~(it)`: `query /t | coalesce
  30` answering 30 over a value that stands.
- After `!|`, a literal that holds paths answering itself: the habit of a
  template answered in silence, as a path alone was refused.
