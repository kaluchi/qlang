# D416 · The gate runs each suite once, the suites of the core and of the command line under the thresholds of coverage, a hook of a test waits as long as a test, and the ring of atoms walks in as many shares as the workers of a run hold

Domain. Process.
Decided by. The maintainer, whose words it quotes, for the ring of atoms
cut in more shares, which a run spreads over the cores of the machine; the
model's are the gate that runs each suite once, the wait of a hook, the
count of the shares and the shares read from their files, on the
maintainer's word that hands it the speed of the work.
Overrides [QSWRK#tooling]
Decision.
- `npm run ci` runs each suite once: the build, eslint,
  `check:conventions`, `check:probes`, `check:fuzz`, `check:benchmark`, the
  suites of the core and of the command line under the thresholds of
  coverage, the suites of the language server, the site and the extension
  of the editor, the integration of the command line and the build of the
  site, in that order. A run under the coverage fails a test that fails as
  a run without it does, and a threshold below a hundred as well, so the
  suites of the core and of the command line run under it alone; the checks
  of GitHub, `.github/workflows/ci.yml`, run the same, the job of their
  suites the job of their coverage.
- A hook of a test waits as long as a test does, fifteen seconds, the boot
  of the root under the coverage among them, in the `vitest.config.mjs` of
  the core and of the command line.
- The ring of atoms walks the examples of the catalog in twelve shares and
  the literals of the conformance cases in four, a file each,
  `core/test/unit/QSLIT/atoms.catalog-<n>.test.mjs` and
  `atoms.cases-<n>.test.mjs`, so the shares stand side by side on the
  workers of a run; the helper of the ring reads the shares from the files
  that stand, each file passing its number, so a share added or taken away
  is one file.

```sh
$ git ls-files --error-unmatch 'core/test/unit/QSLIT/atoms.catalog-*.test.mjs' | wc -l
12
$ git ls-files --error-unmatch 'core/test/unit/QSLIT/atoms.cases-*.test.mjs' | wc -l
4
```
Source. The maintainer asked whether the gate answers otherwise for the
suites it runs twice and whether one run holds the tests and the coverage
alike, «ок, на npm run ci там есть разница в результате? можно ли
тестировать и покрытие снимать одновременно?» (maintainer, 2026-10-22
02:09 UTC, session 26bbf1c5), and named whose the double run was, «это не
я ставил просто =- а предыдущий агент так написал» (02:10): the gate came
with 3fce3dc19, which mirrored the jobs of `.github/workflows/ci.yml`, the
suites and the coverage of the core and of the command line two jobs
there, and [D239] the model's record of it. The session read both runs
alike, one configuration and the provider `v8`, which rewrites no code,
every test of the core and of the command line passing in each, and the
core's suite 73 s plain and 120 s under the coverage on this machine.
Two of four runs of the coverage of the core it timed failed with no
defect, «Hook timed out in 10000ms» at the hook of
`core/test/unit/QSHST/door.test.mjs` that boots the root, every test of
the file skipped, the wait of a hook the default of vitest beside the
fifteen seconds of a test. The ring of atoms held the longest files of the
core's suite, the four shares of the catalog about 60 s each and the
literals of the cases 42 s, on the thirteen workers vitest takes of the
fourteen threads of the machine, and the maintainer asked for more shares,
«единственное что можно ещё попробовать.. это больше этих атомик тестов
нарезать..  что б на 12 ядер оно могло вставало... в целом ты уже лучше
меня знаешь как здесь что ускорять, я не возражаю если ты это как-то
применишь здесь с умом и здравым смыслом здесь..» (02:39).
Set aside.
- The suites of the core and of the command line run plain before their
  coverage, a failure found sooner: at the cost of a second run of every
  test of the two, about 85 s of each gate.
- The count of the shares spelled beside their files: at the cost of a
  share whose file is missing walking nothing in silence.
- A share for each worker of the machine that runs the suite, read from it:
  at the cost of files of the tree that no count of a machine writes.
Requirements. The gate and the checks of GitHub, which run each suite
once; the files of the shares, which the probes above count, and the
ring, which walks every example of the catalog and every literal of the
cases in one share or another.
