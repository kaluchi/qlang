# D419 · The command line exits once its streams have written what they hold

Domain. Implementation.
Decided by. The model, on the maintainer's word to repair master and to keep
the work with `process` in one file.
Decision. `playground/src/bin.mjs`, the one file of the playground that touches
`process`, exits with the code `main` resolves once its standard output and
its standard error have written what they hold, a stream that fails, a
reader that closed the pipe among it, ending its wait; `main` takes the
streams it is handed and touches no `process`, so its tests hand it streams
of their own.

```sh
$ grep -c "process.exit(code)" playground/src/bin.mjs
1
```
Source. The checks of GitHub failed on master at the probes of the command
line that read its output through a pipe, the bytes `json | out` writes in
[QSCLI#answer] and the last number the REPL prints in [QSCLI#repl], the
first on the runs of both of the last two baselines and the second on the
latest. On
Linux, in a container of Node 24 over the checkout, the answer arrived cut
at 65536 bytes, the buffer of a pipe, and the REPL's last number in none of
five runs: `process.exit` ended the process while a write past the buffer
waited, which a pipe of Windows writes at once. The maintainer asked to
repair master, «да, поправь, мастер надо починить» (maintainer, 2026-10-22
03:46 UTC, session 26bbf1c5), held the work with `process` to one file,
«лумаю правильнее будет если с process.* работа будет вестись из одного
файла только» (03:51), since «потому как это вроде как и неявная зависимость которую
мокать надо в витестах» (03:51).
Set aside.
- The code of exit set as `process.exitCode`, the process ending when its
  loop is empty: on Linux a reader that closed the pipe early ended the
  process by an `EPIPE` no listener heard, and such a process waits on
  whatever its loop still holds, where the exit after the streams have
  written waits on them alone.
- The streams waited on inside `main`: at the cost of `main` touching the
  streams of the process, which its tests hand it.
Requirements. The probes of [QSCLI#answer] and [QSCLI#repl] that read the
output of the command line through a pipe, which the checks of GitHub run on
Linux.
