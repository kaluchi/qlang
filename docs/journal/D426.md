# D426 · Open: a byte order mark at the head of a text a host reads

Domain. Language.
Question. What does a host do with a byte order mark at the head of a
text it reads as UTF-8? The command line reads standard input by the
decoder of Node, which keeps the mark as the character U+FEFF, so a JSON
text written with it lifts to the string it is, the mark its first
character [QSCLI#stdin], and a source written with it is refused by the
grammar:

```sh
$ printf '\xef\xbb\xbf{"a": 1}' | qlang 'get [~(type) ~(count)]'
[::string 9]

$ printf '{"a": 1}' | qlang 'get [~(type) ~(count)]'
[::map 1]
```

```qlang
> "﻿1 | add 1" | parse !| type
::quote/ParseError
```

The decoders of the web, `TextDecoder` and the text of a response, drop
the mark, and those of Node, `setEncoding('utf8')` and `readFile` with
`'utf8'`, keep it:

```sh
$ node -e "const bytes = Uint8Array.of(0xef, 0xbb, 0xbf, 0x31); console.log(new TextDecoder().decode(bytes).length, Buffer.from(bytes).toString('utf8').length)"
1 2
```

So a source the web host loads, `core/src/load-source-web.mjs:18`, reads
where the Node host, `core/host/load-source-node.mjs:19`, refuses it, and
the doors of Node that decode are standard input,
`cli/src/stdin.mjs:11`, the source of the command line,
`cli/src/cli-sources.mjs:10`, and the sources of the catalog the language
server reads, `lsp/src/server.mjs:44`. Windows PowerShell, the shell
Windows ships, writes a file by `Out-File -Encoding utf8` with the mark at
its head, where `pwsh` writes none.
Source. «да, пишем все в UTF-8 разумеется.. и читаем тоже, рассчитывая
что идёт UTF-8... верно же?» (maintainer, 2026-10-23 07:56 UTC, session
2ae0c77a), «я думал просто что BOM этот это артефакт всяких многобайтовых
кодировок по типу UTF-16 и т.п. .. в UTF-8 его не существует» (08:00),
and on the doors where it is dropped, «ок, ты вроде предложил где её
можно снять и не тянуть дальше по цепочке» (08:03). The probes and the
doors are the model's reading in session 2ae0c77a, met while it weighed
the files the store of a cell writes [D407].
Alternatives. The roads, each with its cost.
- Each door of a host that decodes UTF-8 drops a mark at the head of the
  text, by `TextDecoder`, as the web host does, so a text reads alike
  whichever host reads it and the core never meets the mark; at the cost
  of the doors of Node written anew, a case of [QSCLI#stdin] and of
  [QSHST#source], and `in`, which answers standard input as it came,
  answering it without the mark.
- The grammar reading the mark at the head of a source as whitespace,
  and `parseJson` dropping it; at the cost of the core taking a matter of
  the doors, a mark read inside a text the reader joined still refused,
  and every verb that reads a text but these two meeting it.
- The doors as they stand, a mark reaching the core as the character it
  is.
