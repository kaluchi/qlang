# D496 · A modifier reaches its verb as it is written: a program at rest the verb feeds, a group and a name at rest inside a literal, a declaration whose body asks a subject a program, and `get` the sibling of `map` that walks no element

Domain. Language.
Decided by. The maintainer, who asked for the verb to take the tail of its
modifiers whole and to decide how to compute it, the group at rest, `it`
pointing at the subject, the spelling without the tilde, `get` the sibling
of `map` that walks no element and acts as `apply` on a value given alone,
`map` taking a template as `get` takes one, the reading by an index and by a
key left to a verb added at the end, and the catalog written anew in that
spelling. The model's: the head that tells
a value from a program, `it` the value of the subject of the step it is
written in, the declaration whose body asks for a subject, the refusals of a
quote whose bare writing is the same program and of code quoted twice, and
the sections it overrides.

Decision.

A modifier reaches its verb as it is written, and its head tells what it
is. An expression whose head names a value, a literal, a tag, a quote, a
path, a name of a value of its step or `it`, the subject of the step it is
written in, is that value, computed at the call against the subject of its
step: `5 | mul it` answers `25`, and `[1 2 3 4 5] | get (it | count | sub 2)`
hands `get` the number `3`. An expression whose head asks a subject, a name
that reaches a verb, a program its text declares or a name its step holds
no value under, the names `with` gives among them, is a program at rest,
which its verb feeds as its input takes it: an input of a value with the
subject of the step at the call, so `5 | add (mul 2)` answers `15` and
`[1 2 3] | take count` answers `[1 2 3]` as before; an input of code with each
value the verb runs it on, `[1 2 3] | map toString`, `filter (gt 1)`,
`sort (get /age)` and `reduce 0 add`, the branches of `if` and the clauses
of `cond`, the conditions of `allOf` and `anyOf` and the alternatives of
`coalesce` each in its turn, and the code `apply` runs on the subject; and a
template with the subject, part by part.

A literal holds a group and a name written inside it at rest, as the steps
they are, and still computes nothing: `[count (add 1)]` is a vector of two
steps, and a verb that takes the literal as a template runs them,
`[2 1 3] | get [count print reverse sort last first]` answering
`[3 "[2 1 3]" [3 1 2] [1 2 3] 3 2]`.

`get` is the sibling of `map` that walks no element: it reads a path, runs a
program on the subject and builds a template part by part, as `apply` runs
code on the subject, so `[1 2 3 4 5] | get (count | sub 2)` answers `3`, and
a value given alone of any other kind it refuses as `apply` refuses it,
`get 0` naming the path `get /0`. `map` takes a template as `get` takes one
and builds it on each element, `map {:name /name :count (get /tags | count)}`
for `map (get {…})`. A key alone is no path of `get`, `query`
and the verbs that write, each of which reads a key by its path,
`put /a 1`, and a key the query computes once a path holds it,
`[k] | toPath`; `has` takes a key as it is, asking whether the key or the
element stands. A verb that reads a vector by its index and a map by its
key, for the habit a reader brings, is added at the end of the stint.

A declaration whose body asks for a subject declares a program, run on the
subject wherever its name stands, a step, a modifier and a part of a
template among them, and handed on as code: after
`:mf manifest; :isFn (binding | value | tag | eq ::fn);` the query
`::host | kinds | map mf | flat | filter isFn | size` answers `219`, and so
does `map ~mf`. A body that names a value is computed once: `:a ~(add k)`
holds the literal as it is written, code held as a value, which runs only
where a verb that runs code is handed it, `map a`, `apply a` and a branch of
`if` among them, while at a step it is refused with the repair `apply a`, at
the head of code it answers itself, and in a template it stands as the
value it is. Under a label the program is the verb, `:number/double mul 2;`.

A tilde writes code as a value. A quote written where a verb takes code or a
template, or under a label, whose bare writing is the same program is
refused, its repair the bare writing, so a program has one spelling; the
tilde stays where it changes what is handed: code held as a value,
`eq ~(mul 2)`, `put /rule ~(add 1)` and the links and the snippets of a
page, and code whose head names a value, `map ~(:yes)`.

A verb that runs code refuses code quoted twice, code whose one step names a
value of the step that holds code, `map ~mf` after `:mf ~manifest;`, under
its address and its input, `::vec/map/CodeQuotedTwiceError`, its repair the
bare name, `map mf`.

The pages of the catalog, the cases, the chapters and the tests are written
anew in this spelling.

Set aside.
- Every modifier computed at the call and a tilde the one spelling of code
  handed to a verb: the writing a reader reaches for first is refused,
  `map toString`, or answers otherwise without a word, `get (count | sub 2)`
  answering `4` and `map ~mf` the quote for every element.
- A sign of its own for a value computed on the caller's side: the
  maintainer looked for a sibling of `it` instead, and `it` names the
  subject of its step.
- Every expression handed whole, the verb feeding even one that names a
  value: `apply it` would answer its subject instead of running it, and code
  or a key the subject holds would have no spelling.
- The key rule kept for a key the query computes, `get (it | count | sub 2)`
  answering `4`: the maintainer set the reading by an index and a key on a
  verb added to a clean base, and the rule read `get 0` and `get [0 1 2]`
  two ways, `1` and `[0 1 2]`.
- Every name that holds code read as a program: code held as data, a
  frame's `unfinished`, a rule `with` names and a quote a recipe takes,
  would run where it is read as the value it is.
- A verb under a label kept in its quote, `:number/double ~(mul 2)`, beside
  its bare program: two spellings of one verb.
