Decision.

A modifier reaches its verb as it is written, and the input that takes it
decides what it is. An input of a value takes every modifier computed at
the call against the subject of the step, as before: `5 | add (mul 2)`
answers `15` and `[1 2 3] | take count` answers `[1 2 3]`. An input of code
or of a template takes a group and a name that holds no value of the step,
a verb, a program its text declares or a name the verb gives, as code at
rest, whatever stands at its head, and runs it on the values of its own
choosing: `[1 2 3] | map toString`, `filter (gt 1)`, `sort (get /age)`,
`reduce 0 add`, `[1 2] | map (5 | add 1)` answering `[6 6]`, the branches
of `if` and the clauses of `cond`, the conditions of `allOf` and `anyOf`
and the alternatives of `coalesce` each in its turn, the code `apply`
runs, and the body of `with`, `{:qty 2 :price 3} | with [/qty /price]
(qty | mul price)` answering `6` whatever names the step holds. A literal, a
quote, a path, a tag and a name that holds a value of the step are the
values they are. `it` names the subject the code runs on, so
`[true false true] | filter it` answers `[true true]`; `self` names the
subject of the step that writes it, and an expression whose head is
`self` is computed at the call against that subject and handed on as a
value, the one sign of the caller's side: `~(1 | add 1) | apply self`
answers `2`, and `apply (self | get /rule)` runs the code the subject
holds. An input of code is one the core marks to run, to fold or to read
within, the names and the body of `with` among them, and one of a verb
written in the language whose kinds name `::quote` or `::fn`, which takes
the code as a quote with the values of the step written at its head
[QSQUO#held].

A literal holds a group and a name written inside it at rest only where
a verb takes it as a template, `get`, `query`, `settle`, `with` and `map`,
which run every step the template holds, written or assembled from data,
as they run a quote and read a path: `[2 1 3] | get [count print reverse
sort last first]` answers `[3 "[2 1 3]" [3 1 2] [1 2 3] 3 2]`, and
`[::Box 5] | with {:t first} (t)` answers `::Box`. Anywhere else, at the
head of a query, as the body of a declaration, after `!|` and where a value
is taken, a literal that holds one is refused as before, its repair the
template of `get` written bare, so `{:a 1} | put /n [count]` is refused as
`::call/LiteralComputesError`.

`get` is the sibling of `map` that walks no element: it reads a path, runs
code on the subject and builds a template part by part, so
`[1 2 3 4 5] | get (count | sub 2)` answers `3`; a value given alone of any
other kind it refuses as `apply` refuses it, `get 0` naming `get /0`, and
`query` does as `get`, softly. `map` takes a template as `get` takes one
and builds it on each element,
`map {:name /name :count (get /tags | count)}`. A key alone is no path of
`get`, `query` and the verbs that write, each of which reads a key by its
path, `put /a 1`, while `has` takes a key as it is, asking whether the key
or the element stands. `at` reads a vector by its index and a map by its
key, a value computed at the call, as the habit a reader brings asks:
`[10 20] | at -1` answers `20` and `{:k "b" :b 7} | at (get /k)` answers
`7`, a part it misses refused as a path of one segment is.

A declaration whose body asks for a subject, its head a verb, declares a
program, run on the subject wherever its name stands and handed on as code:
after `:mf manifest; :isFn (binding | value | tag | eq ::fn);` the query
`::host | kinds | map mf | flat | filter isFn | size` answers `219`. A body
whose head names a value, a literal, a quote, a tag, a chain, a value of
the text or `self`, is computed once: `:a ~(add k)` holds the literal as it
is written, code held as a value, which runs where a verb that runs code is
handed it, `map a` and `apply a` among them, is refused at a step, its
repair `apply a`, answers itself at the head of code and stands as itself
in a template. A program of the text is seen where its verbs are, in the
lane of the code a verb runs and in the scope a verb's call opens, and is
withheld from none; a source of the root declares none
[QSNAM#root], and a host that writes a declared name back writes a program
by its body. Under a label the program is the verb,
`:number/double mul 2;`.

A tilde writes code as a value. Code written in the step where a verb takes
code or a template, a quote under any tags over it, `~(mul 2)`,
`::quote~(add 1)` and the identity `~()` among them, is refused, its
repair the bare writing, `(mul 2)`, `it`, which a group or a name writes
alike; under a label a quote whose bare body is the same program is
refused as `::bind/BodyQuotedError`. The tilde stays where code is held as
a value: in an input of a value, `eq ~(mul 2)`, `put /rule ~(add 1)`, in
the commands of a chain, `impl`, `proves`, `holds` and `takes`, under a bare
name and in the links and the snippets of a page.

A verb that runs code refuses code quoted twice, code whose one step is a
value that holds code, a name of the step that holds a quote or a quote
written in a group, `map ~mf` after `:mf ~manifest;` and `map (~(add 1))`,
under its address and its input, `::vec/map/CodeQuotedTwiceError`, its
repair the bare code, `map mf`. Code of more steps that reads such a value,
`map (mf | count)`, reads the quote as data and stands.

The pages of the catalog, the cases, the chapters, the tests, the tasks of
the benchmark, the pages of the site, the page of the package and the
sister project are written anew in this spelling.
