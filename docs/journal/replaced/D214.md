# D214 · The command line answers in the literal, and a query converts it

Left at 95a0454d, the tree this text was last true of: a path, a case or a
probe it names reads there, `git show 95a0454d:<path>`, not in today's.

Domain. Command line.
Decided by. The maintainer, on the reading the model laid out to him.
Decision. The command line writes every answer as the language prints
it, whatever its input was: a JSON input is read as values, as it is,
and the answer is written as its literal, a string as its text, a
failure as its alert with the prose of its refusal's page below it,
never a refusal of a value JSON has no form for. A reader who wants
JSON or another format converts the answer in the query: `| json`
writes the JSON text of a value, which goes out as the text it is, and
`!| it | json` the JSON of a failure caught to its error at rest; so how
an answer leaves the language is told by the language's own pages,
`::any/json` among them, and no flag of the command line chooses it.
The page of the command line tells its default behaviour, what it reads
and what it writes, and leads by its links to the pages of conversion,
of budgets and elision and of failures, which a reader follows at need.
Source. The model's assessment of the command line as the children of
the benchmark met it: every input of a set was JSON, so every answer
and every failure a child read was JSON, a keyword written as a string,
a set as an array, a tag or a quote refused, and a failure a JSON
envelope in the place of its alert; and no child of set U read `--help`
or `::cli | doc`, the only places that told it. The maintainer: «ругаться
надо только когда к cli пристыкован строкий потребитель json-а  ...
ошибка ведь как-то выдается сейчас все равно..  почему просто qlang-ом
не отвечают? в чем смысл ..» (maintainer, 2026-10-11 19:48, session
22b934f8), and on the assessment: «когда пользователю хочется только
json - он ведь может сам | json дописать в конце .. или ещё какой другой
формат конвертации..  или там  !| / | json  если и ошибку хочется загнать
в json .. весь этот мануал из самого qlang должен получаться..» and
«сделать недостающий tutorial для cli и нормально там по линкам и частям
разложить..  дефолтное поведение там рассказать, а если надо какие-то там
сложности-трасформации, хитрая элизия, ошибки и т.п.   - то пусть по
линкам там сами ходят и изучают ..» (20:10). His words replace his rule
that a JSON input expects JSON back, which [D192] kept.
Set aside. The answer written as JSON when the input was JSON and as the
literal where JSON has no form for it, which keeps a keyword a string
and a set an array in every answer a JSON input gives. A flag of the
command line that holds the answer to JSON, a second spelling of the
conversion `| json` writes. A sentence on the first page that warns of
the refusal, which tells a reader of a wall instead of taking it down.
Replaces in part [D103], [D126] and [D192], under which a JSON input chose JSON
for the answer and an answer JSON has no form for was refused, [D120],
under which a budget left the data of a JSON answer whole, and [D195],
under which a failure written as JSON carried its page under `page`.
Requirements. The tests of the command line: a JSON input whose answer
holds a keyword, a set, a tag or a quote prints the literal; a failure
on a JSON input prints its alert with the prose of its page; a string
answer goes out as its text, so `| json` and `!| it | json` write JSON
text. The page of the command line tells the default and links the
pages of conversion, budget and failures.
