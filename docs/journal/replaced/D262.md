# D262 · Open: where a host's query runs

Left at ff31d9e4, the tree this text was last true of: a path, a case or a
probe it names reads there, `git show ff31d9e4:<path>`, not in today's.

Domain. Host.
Question. A host answers the language's calls one by one over its own
boundary, so a query that fans out over a large answer, the members of
`java.lang.String` and the callers of each, pays a round trip per
element, and its elements run in their order [D84]. The
maintainer's direction is the other end: «само qlang выражение мы будем
отправлять через jdt в сам эклипс и пусть его процесс считает ... и
тогда не надо все эти ресты выставлять в апи, для выдергивания данных»
(maintainer, 2026-09-26 06:10, session 86982eb5).
Source. The maintainer's direction the question quotes; the audit held
it in its open chapter from 26 September 2026.
Alternatives. The query sent to the host's process, where the data lives
and only its answer crosses the boundary, at the cost of a JavaScript
engine inside the host's process, since the core is JavaScript, and a
session whose scope lives in two processes; or the evaluator kept in the
client, and words of the host that take a vector whole and bound
their own calls.
