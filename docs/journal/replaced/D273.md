# D273 · The tools read the role of a declaration from the form its source writes

Left at 086312ae, the tree this text was last true of: a path, a case or a

Domain. Tooling.
Decided by. The model, on the roads the record held open and the work of
[D371], whose language server names a declaration by its role.
Overrides [QSHST#tools]
Decision.
- The tools read the role of a declaration of a document from the form its
  source writes, which the constructor of a declaration reads as well: a
  body that opens with `::kind` declares a label, `declaresKind` in
  `git show 086312ae:core/src/steps.mjs`, and a body that runs on the values of its label, a
  quote or a function its chain gives a recipe, declares a verb,
  `bodyRuns` in `git show 086312ae:core/src/chain.mjs`; a node of the root is named by the
  records the root holds. No document is run to name its roles, since a
  run of a source the reader is editing stops at its first failure and runs
  its code at every keystroke, so a kind built elsewhere and bound by name
  is a kind to the runtime and a value to the tools:

Source. The review of the branch `the-path-is-a-value`, its fourth
finding, `docs/journal/research/reviews/2026-10-13-the-path-is-a-value.md`,
which opened the question of reading the roles from a run; the language
server of [D371] names each declaration by its role, read from the form.
Set aside. The roles read from the records a session's run of the
document writes, `isLabel` and `isVerb` over its scope, at the cost of
running a document the reader is editing, which a failure part of the way
stops; and the language saying a role is the form its declaration writes,
which [D253] set aside.
Requirements. The tests of the language server that name a declaration by
its role, a label, a verb and a value.
