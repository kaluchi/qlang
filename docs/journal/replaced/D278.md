Decision. Code a verb runs is code of a step or code held as data.

A quote written in a step, an object of a call or a part of a template
an object writes, a quote or a template under a tag among them, is code
of that step: the call runs it in the scope of the step that wrote it, a
word of the host and a word written in the language alike. Where an
object came from is a fact of the call that receives it, kept for the
whole of its run: the call keeps the origin of each object, the step it
came from and whether it was written there or is a value of that step,
and code run within the call finds the origin of a quote it runs by the
calls that received it, the nearest first, by whatever road it took
there, an input, a name the body declares from it, `args`, an input of
the args whole, a group of the body and the objects `apply` hands a
function. The quote itself stays the value its print shows, and the fact
ends with the call: a quote the call answers is data again. So
`:k 10 | … | [1 2] | w ~(add k)` reads the `k` of the step that wrote the
quote, and a word whose input is named `k` shadows nothing in it.

Any other code, a quote held in a name, a field, a vector or a page, a
law and a snippet among them, a quote a call answered or a group
computed, and the steps a trail skipped, runs in a lane of its own, as
the call of a function does: the lane of the step a call keeps as its
origin, or else of the step that runs it. Its past is the subject it runs
on and its tree, the words, the nodes and the labels of that step's own
scope and the names it declares itself. A value that scope names is
withheld from it: read there, by a step, by a tag or as the noun of a
declaration, it is refused under its name, `::call/ValueWithheldError`,
so it never falls to a word, to a value of the root of the same name or
to a tag no kind answers, while a tag reads a label of the root before
any name of the reader there as it does anywhere [D153]. The scope of a
body is its own, so code a word holds reads no value its reader named
and is refused under a value it names itself, and a law of a name the
root declares runs in a lane over the root alone, as a word of the root
runs in the root's scope [D200]. The meaning of held code is its text
and the vocabulary, as a literal's is its text [D279]: a step around a
call shadows nothing it reads, a name declared after it is read by none,
and `:big ~(gt lim) | :lim 4 | [1 5 10] | filter big` is refused under
`lim`. A value held code needs is an input of a function, `apply f [4]`,
or written into its code by `fill`, and code that calls itself is a
word, `:number/fact ~(… fact …)`. The declarations of held code are its
tree, which `doc` and `binding` read there; a recipe's stay out of the
tree of the query [D200].
