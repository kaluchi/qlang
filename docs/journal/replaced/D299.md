Question. `coalesce` answers the first alternative that is not null, and
the two rules its page states answer wrong where a reader errs. A group
computed at the call is a value, so a call of a group and a value puts
the subject first, and the subject, never null, answers; and code that
fails is taken as no value whatever the failure, the refusal of a name
the reader misspells among them:

```qlang
> {:t null} | coalesce (get /t) 30
{:t null}

> {} | coalesce ~(nosuchword) 30
30

> {:t null} | coalesce /t 30
30
```

Both are answers a reader cannot tell from a right one, which the first
attempt pays for, the measure of [the aim](../AIM.md#mission). The axis is
an input that takes a value or code: a failure computed at the call is
refused under the input of `allOf` and answers the call of `coalesce`,
and a path a group computed is code to `coalesce` and a value to any
input that takes a value:

```qlang
> {} | allOf (get /x) ~(true) !| get [~(type) /actualType]
[::any/allOf/conditions/ElementKindNotTakenError ::path/KeyNotInMapError]

> {} | coalesce (get /x) ~(1) !| type
::path/KeyNotInMapError

> {:p /a :a 5} | coalesce (get /p)
5
```

A name withheld from held code [QSQUO#held] is a failure too, so an
alternative held as data that reads a value of the reader passes to the
next, where `apply` refuses the same quote:

```qlang
> :k 1 | :q ~(add k) | 5 | get [~(coalesce q ~("none")) ~(apply q !| type)]
["none" ::call/ValueWithheldError]
```
