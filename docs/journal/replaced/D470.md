# D470 · A quote answers its code by `answer`, and a link names its page by its address

Left at acae4977, the tree this text was last true of: a path, a case or a
probe it names reads there, `git show acae4977:<path>`, not in today's.

Domain. Language.
Decided by. The maintainer: `open`, made for `::link`, had become a verb
of every quote, and the links strewed the catalog with `| doc`. The
model: the name `answer` for what the code of a quote answers, `open`
given back to the link as the page it names, the page named by its
address alone, and the rewrite of the pages, the cases, the tests and the
probes.

Decision. `answer`, a verb of `::quote`, runs the code a quote holds from
null, beneath whatever tags stand over it, and answers what the code
answers, as `::cell/answer` reads what a cell answered: a print reads
back as the value it writes by `parse | answer`, and a snippet answers
what it shows. A link names a page by the address the page is under,
`::link~(::vec/sort)`, its code answering the name, and `open`, a verb of
`::link`, answers the page, the doc of what the code answers; the code of
a link runs by `answer` as the code of any quote does, answering the
name:

```qlang
> "[3 1 2] | sort" | parse | answer
[1 2 3]

> {:price 4 :qty 3} | print | parse | answer
{:price 4 :qty 3}

> |~~ See ::link~(::vec/sort). ~~| | links | first | get [~(answer) ~(open | tag)]
[::vec/sort ::doc]

> ::vec | doc | links | map ~open | every ~(tag | eq ::doc)
true
```

`open` leaves `::quote`: a quote that is no link, a snippet among them,
names no page to open, and `open` refuses it as
`::link/open/SubjectNotLinkError`, whose page names `answer`; a bare
`answer` on a value no verb of its name serves is refused as
`::call/KindAnswersNoVerbError`, its addresses those of the kinds that
answer in one sense what their code answered, a quote and a slot, and a
cell where a host keeps one:

```qlang
> ~(1 | add 1) | open !| tag
::link/open/SubjectNotLinkError

> "1 | add 1" | answer !| get [~(tag) ~(addresses)]
[::call/KindAnswersNoVerbError #[::cell/answer ::fn/slot/answer ::quote/answer]]
```

The links of the catalog, of the pages the chain writes for a kind, of
the cases and of the probes lose their `| doc`, and the cases, the tests,
the pages and the probes that ran a quote by `open` run it by `answer`.
Source. The maintainer on the verb: «давай ещё с | open разберемся ... а
то это было для ::link -- но стало и для всех квот ... какое название
полойдет лучше?» (maintainer, 2026-10-27 06:41 UTC, session 277691ba); on
the links, «и линки може переделать что б те не сорили каталог всеми этими
| doc ?» (06:42 UTC); and on who decides, «почему все мне решать?» (06:13
UTC). On what a link is, «для меня гипертекст это просто данные с
вкраплениями кода, этот код будучи исполняемым по своей природе порождает
новые данные» (maintainer, 2026-09-29 17:16 UTC, session 32016e08), and
«просто квота может содержать на первом шаге смену субъекта и тогда мы
совершаем прыжок в его пространство» (17:25 UTC): a link stays code, its
one step the jump to the name, and the page is what opening it reads
there. The verbs of the language name what they answer, `count`, `keys`,
`payload`, `doc`, and the code of a quote answers its answer, the word the
pages already give a cell, a slot and every step; a link is followed to a
page, which `open` names as the maintainer's first form of it did,
`::qlang | doc | links * open` (2026-09-28 13:48 UTC, session d427ce7e).
Set aside.
- `run`, `eval` or `value` for the code of a quote: `run` names no
  answer, `eval` is a word of the hosts' languages, and `value` a part of
  a binding.
- `open` kept on every quote beside `answer`: two names of one run.
- A link that keeps `| doc`: six characters a link, 678 of them in the
  catalog, saying what every link of the catalog does.
- The page of a link under `doc`: `doc` answers the page of the kind of
  any value, and a link reading its target there would give one verb two
  readings.
Requirements. Every case that names this record. Of the cases it renames,
`a-snippet-opens-to-what-it-shows` gives way to
`a-snippet-answers-what-it-shows`,
`a-link-opens-to-the-answer-of-its-query` to
`a-link-answers-what-its-code-answers`,
`a-value-that-is-no-quote-opens-nothing` to
`a-value-that-is-no-quote-is-refused-by-the-address-of-answer`, and
`open-lives-on-the-kind-of-a-quote` to
`answer-lives-on-the-kind-of-a-quote`.
