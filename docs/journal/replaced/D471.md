# D471 · `fill` writes at the head of a quote the values of the names it reads

Left at b3d0776f, the tree this text was last true of: a path, a case or a
probe it names reads there, `git show b3d0776f:<path>`, not in today's.

Domain. Language.
Decided by. The maintainer: a quote takes the values of the names it reads
by `fill` and a map of them, `~(add myaddend) | fill {:myaddend 1}`
answering `~(:myaddend 1 | add myaddend)`, and a name the quote does not read
is refused with the names it reads near it. The model: the address of the
verb, `::quote/fill` beside `::fn/fill`; the order of the declarations, the
order the code reads the names in; the refusal of a name not read,
`::quote/fill/NamesNameNotReadError` with `:name` and `:nearest`, a name the
quote declares itself among them; and the pages that lead held code to it.
Overrides [QSQUO#held]
Decision. `fill`, a verb of `::quote`, takes a map of names and their values
and answers the quote with a declaration of each at its head, written as the
step that writes the value, in the order the code reads the names, so code
held as data runs with the values it needs, a quote under a tag of its own
among it:

```qlang
> ~(add bonus) | fill {:bonus 10}
~(:bonus 10 | add bonus)

> ~(mul qty | add fee) | fill {:fee 5 :qty 3}
~(:qty 3 | :fee 5 | mul qty | add fee)

> 5 | apply (~(add bonus) | fill {:bonus 10})
15
```

A name the code does not read from outside, one it declares itself among
them, is refused as `::quote/fill/NamesNameNotReadError`, its `:name` the
name given and its `:nearest` the names the code reads near it in spelling,
and names that are no map as `::quote/fill/NamesKindNotTakenError`:

```qlang
> ~(add myaddend) | fill {:myadend 1} !| get [~(tag) ~(name) ~(nearest)]
[::quote/fill/NamesNameNotReadError :myadend [:myaddend]]

> get [~(~(:bonus 1 | add bonus) | fill {:bonus 10} !| tag) ~(~(add bonus) | fill [10] !| tag)]
[::quote/fill/NamesNameNotReadError ::quote/fill/NamesKindNotTakenError]
```

The page of `::call/ValueWithheldError`, which names `fill` among the roads
of a value into held code, leads to it; `fill` of a function, `::fn/fill`,
writes the args of its call as before, and a subject of neither kind meets
the two verbs of the name, `::call/KindAnswersNoVerbError`.

Set aside.
- The algebra of quotes at once, the quote of a step and a quote parted
  into the quotes of its steps beside `fill`: no task asks for them, where
  the page of the withheld value asks for `fill`.
- The names of the call read as `with` reads them, paths and quotes run
  against the subject: the subject of `fill` is the code, which holds no
  value to read, so its names hold the values themselves, as the maintainer
  wrote them.
- A name the code does not read written at its head all the same: a name
  misspelled would stand there unread, and the maintainer named its
  refusal.
