# D497 · The modifiers a call writes past the inputs of its verb are the modifiers of the bare verb its last input takes: `map gt 0` reads `map (gt 0)`

Left at 33ebe0b6, the tree this text was last true of: a path, a case or a
probe it names reads there, `git show 33ebe0b6:<path>`, not in today's.

Domain. Language.
Decided by. The maintainer, who asked for the modifiers past the inputs to
be read where the verb of a call takes its tail whole, and took the reading
one by one with a group where the reading by the tail is not the one meant.
The model's: the last input as the one whose verb takes the tail, the bare
verb as the one it goes to, an input of a value among them, and the
boundaries where the tail stays refused.
Overrides [QSBLD#input], [QSQUO#modifier].
Decision.

A verb reads the modifiers of its call one by one, each into the input
that takes it, and the modifiers past its inputs are the modifiers of the
bare verb its last input takes, the name of a verb or of a program written
with no modifiers of its own: `[-1 2] | map gt 0` reads `map (gt 0)` and
answers `[false true]`, `[[-1 2] [3]] | map filter gt 0` reads
`map (filter (gt 0))` and answers `[[2] [3]]`, and
`-5 | if (gt 0) (add 100) sub 1` answers `-6`. An input of a value
computes the call so formed at the call as it computes any modifier,
`5 | add mul 2` answering `15`, and an input of code takes it at rest with
the values of the step written at its head, `:k 10; [1 2] | map add k`
answering `[11 12]`. A verb whose last input reads the args whole takes
every modifier there, and no tail stands past it. Where the last input
takes a literal, a group, a path, a quote or a name that holds a value,
the modifiers past the inputs are refused as before, `[1 2] | take 1 2` as
`::vec/take/ArgsBeyondInputsError`, and the call a tail forms refuses a
tail past its own inputs, `[1] | map add 1 2` as
`::number/add/ArgsBeyondInputsError`. A group writes the reading where the
tail would take another: `apply add 1` hands `1` to the args, and
`apply (add 1)` runs the code.

The pages of the refusals of the modifiers past the inputs and the first
page tell the tail, and the catalog keeps the group as the spelling of its
own examples.


Source. The maintainer ran the playground on the decision before it,
`[-1 -2 1 2 3 4 5] | map gt 0` refused as `::vec/map/ArgsBeyondInputsError`
beside `map (gt 0)` answering, «есть конечно вопросы к surplus и  наказанию
отказами» and «как будто бы часть моментов можно было прощать раз у нас
интерпетация вся целиком теперь на первом V - то все остальное O это
наверное уже хвост другого» (maintainer, 2026-10-30 10:34 UTC, session
c31f3094), and took the rule the model put to him, «да, читаем по одному, а
где применение неуместно то группа задаст нужное чтение» (10:41). The
probes of the session before the decision: `5 | add mul 2` answered
`::number/mul/MultiplierNotGivenError`, the modifier `mul` computed at the
call with no multiplier, and `map gt 0` the refusal above.
Set aside.
- Each refusal kept, its page naming the group: the first attempt a reader
  makes from the habit of a shell, `map gt 0`, would fail where its reading
  is plain.
- A tail taken by the first bare verb of the modifiers: `if (gt 0) add sub`
  would read `if (gt 0) (add sub)` whatever the inputs of `if` take.
- A value given where code is taken read as the constant program of its
  answer: `map :name` would answer the keyword for every element without a
  word.

sections it overrides.
