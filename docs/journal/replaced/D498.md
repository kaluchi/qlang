Decision.

The key of `sort`, `min` and `max`, over a vector, a set and a map, takes
a vector template as `map` takes a template [QSCOL#image]: the template is
built on each element, its paths read and its code run, and the elements
rank by the vector it answers, index by index,
`[{:score 7 :name "Bob"} {:score 9 :name "Eve"} {:score 9 :name "Ann"}] | sort [(get /score | desc) /name] | map /name`
answering `["Ann" "Eve" "Bob"]`. Code written bare and a path stay the
key as before, `sort (get [(get /score | desc) /name])` answering alike,
and null gives no key. A keyword, a number, a string and a map given as
the key stay refused as `…/KeyKindNotTakenError`, `[{:name "b"}] | sort
:name` among them. The key of `groupBy` and of `indexBy` files each
element under a keyword, which a vector never is, and takes code and a
path alone.

The pages of the three verbs, the first page, the page of `desc` and the
chapter write a key of several indices as the template, one `get` where
a field is read and turned.

писать программы...» (maintainer, 2026-10-30, session c31f3094). The

Set aside.
- A template of any kind as the key: a map ranks by its keys before its
  values, so a key `{:score … :name …}` would rank by the order of its
  keywords, not by the order the reader wrote.
- A template as the key of `groupBy` and `indexBy`: the vector it answers
  files under no keyword and is refused at the element.
