### counterexample · The trail a value of `::trail`

```qlang
> ~(count) | payload | first | add 1 !| trail | first | get /subject
::call{:name :count}

> ~(count) | payload | first | add 1 !| trail | first | :s it | get [~(s | get /subject) ~(s | get /step | first)] | tag ::quote | print
~(count | add 1)

> ~(count) | payload | first | add 1 !| trail | first | :s it | get [~(s | get /subject) ~(s | get /step | first)] | tag ::quote | :f it | [7 8] | apply f
3
```

Frame ставит subject в голову quote как шаг. Но subject, который сам является записью шага (`::call`, `::bind`, `::fail`, `::construct`), quote читает как код, а не как значение. Такой frame пишет уже другое предложение, `count | add 1`, а `apply` отвечает `3` вместо того же отказа.

### counterexample · The trail a value of `::trail`

```qlang
> [::Box#1 ::call{:name :count}] | tag ::quote !| type
::quote/ElementNotStepError

> get [~(::elision{:size 1 :read ~(get /a)}) ::call{:name :count}] | tag ::quote !| type
::quote/ElementNotStepError

> ~(::elision{:size 1 :read ~(get /a)} | count) | payload | first | type
::construct
```

Значение под тегом другого вида (тег читателя, хоста, `::span`, сам маркер `::elision`) по [QSQUO#step] не шаг. Поэтому subject такого вида не встаёт в голову frame как значение. Его можно записать только как шаг `::construct`, который при `apply` заново запускает конструктор через метки той полосы, где frame выполняется. Тот же отказ закрывает форму, которую запись предлагает сама: `::frame~((::elision{…} | get /1) | mul 2)`. Alert не может вырезать subject внутри frame маркером, не выйдя из вида quote.

### counterexample · The trail a value of `::trail`

```qlang
> [::number"5"] !| trail | map ~(get [/step /subject])
[[~(::number"5") ::qlang] [~([::number"5"]) ::qlang]]

> "::qlang | [::number\"5\"]" | parse !| get /message
a literal is a value, which a step does not run: a shape is built by `get`, `get {:k /path}`
```

Остановка, которую ставит `answerOfPart` (`core/src/eval-trail.mjs:63`), имеет шагом литерал. Литерал после головы парсер отвергает ([QSSYN#step]), и по [QSQUO#step] его отвергает и конструктор `::quote`. Значит, для такой остановки frame «subject | step» не строится вовсе, а её subject литерал вообще не читает.

### counterexample · The trail a value of `::trail`

```qlang
> :k "x" | 5 | add k !| get [~(type) ~(trail | first | get /step)]
[::number/add/addend/KindNotTakenError ~(add k)]

> :k "x" | 5 | add k !| (:s (trail | first | get /step) | 5 | apply s) !| get [~(type) /name]
[::call/ValueWithheldError :k]

> [{:n 1 :age "x"}] | map ~(:n (get /n) | get /age | gt n) !| trail | map /step
[~(gt n) ~(map ~(:n (get /n) | get /age | gt n))]

> {:n 1 :age "x"} | apply ~((:n (get /n) | get /age) | gt n) !| get [~(type) /name]
[::call/UnknownNameError :n]

> {:n 1 :age "x"} | apply ~(:n (get /n) | get /age | gt n) !| type
::string/gt/value/KindNotTakenError
```

Обещание «`apply` running it again into the same refusal» нарушается дважды:

- frame — код, хранимый как данные, и по [QSQUO#held] имя читателя в нём отказывает как `ValueWithheldError`;
- группа в голове, «that starts from the element», — по [QSNAM#scope] отдельная область видимости, поэтому имя, объявленное шагом уровня до сломавшегося шага, за её пределами уже не видно.

Предложение «уровня» в форме, которую предлагает запись, — не то предложение, которое уровень на самом деле написал.

### cost · The trail a value of `::trail`

```qlang
> [1 "x"] | map ~(mul 2) !| json
{"$tag":"number/mul/SubjectNotNumberError","payload":{"$tag":"error","payload":{"actualType":"::string","trail":[{"step":"~(mul 2)","subject":"x","skipped":"~()"},{"step":"~(map ~(mul 2))","subject":[1,"x"],"skipped":"~()"}]}}}
```

По [QSPRN#json] quote пишется как своя печать. Поэтому subject, который сегодня уходит в JSON как данные (`[1,"x"]`), станет текстом qlang внутри строки. Запись называет у JSON только «a layer». Хост и его потребитель за этой границей теряют структурный subject: чтобы прочесть его, нужен парсер qlang.

### hole · A map in a view giving way within

```qlang
> 4 | range | map ~(get [~(toString | toKeyword) ~(it)]) | toMap | elide 10
{
  :"0" 0
  :"1" 1
  :"2" 2
  :"3" 3
}

> get {:id 1 :config ~(4 | range | map ~(get [~(toString | toKeyword) ~(it)]) | toMap | tag ::T)} | elide 10
{
  :id 1
  :config ::T{
    :"0" 0
    :"1" 1
    :"2" 2
    :"3" 3
  }
}
```

Отображение карты, которая «gives way within», уже есть сегодня: так ведут себя карта на верхнем уровне и карта под тегом. Карта из атомов при этом остаётся сверх бюджета, потому что маркера «the rest of its entries» у карты нет. Маркер остатка вектора — последний элемент, а у карты маркеру нужен ключ. Решению придётся сказать, под каким ключом стоит маркер, как этот ключ не совпадает с ключом данных и как `:read` (`drop`) читает остаток.

### road · The trail a value of `::trail`

```qlang
> [1 2] | filter ~(add 1) !| get [~(type) /index]
[::vec/filter/ConditionNotBooleanError 0]

> [1 "x"] | filter ~(gt 0) !| query /index
null

> [1 "x" 3] | map ~(mul 2) !| trail | get /1/subject/1
x
```

Вопрос «где элемент и его место» решается меньшим: остановка слова, которое выполнило код на элементе, получает `:index` (над картой — `:key`), так же как язык уже даёт `:index` отказу предиката. Тогда `!| get /trail/1/subject/31` достаёт запись целиком. Сегодня внешняя остановка уже держит весь subject, и не хватает только места элемента. Цена — один ключ в форме остановки из [QSERR#trail] и печать отказов `map`, `filter`, `every`, `any`, `reduce` и ключей `sort`/`groupBy` в кейсах. Виды, frame и рантайм, хранящий шаги каждого уровня, при этом не меняются.

### hole · The trail a value of `::trail`

```qlang
> "x" | add 1 !| add 1 !| trail | map ~(get [/step ~(get /subject | type)])
[[~(add 1) ::number/add/SubjectNotNumberError]]

> !{:a 1} | apply ~(!| add 1) | type
::error
```

Остановка шага fail track хранит шаг без комбинатора, а её subject — ошибка в покое. Запись не решает, что пишет frame такой остановки. `::frame~(<ошибка> | add 1)` — не то предложение, которое написал уровень. `::frame~(<ошибка> !| add 1)` при `apply` пропускает значение мимо (`!|` passes a value by) и отвечает не отказом.
