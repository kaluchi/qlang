### counterexample · Part 11. The input lifted by one rule, `in` the raw text and `in | parseJson` the strict read

Запрос, который открывается словом `in`, читает свой субъект. Поэтому командная строка сначала разбирает stdin как JSON, и только потом `in` отдаёт текст. |~| of qlang is, `1e400`, which no number of the language holds, so
|~| reading it is refused. It is met where JSON text is read, by

Литерал замкнут [QSLIT#closed]: он не читает ни имени, ни субъекта. Поэтому его вид вычисляет сам язык: `parse`, `apply`, `type`. Новый экспорт ядра для этого не нужен, а `KIND_OF_LITERAL` и `kindsOfErrorLiteral` уходят без замены.

```qlang
> ["5" "::Box[1]" "::E!{:a 1}" "~(x)" "/a" "|~~ d ~~|"] | map ~(parse | apply it | type)
[::number ::Box ::E ::quote ::path ::doc]
```

Цена — один прогон запроса на литерал в сервере. Для метки, которую документ объявляет с инвариантом, конструктор может отказать, и сервер должен прочитать это как вид отказа.

### road · Part 9 и Part 10, вместе

Значения без вида попадают в рантайм в одном месте — в ответе реализации хоста (и в `bind`, если он остаётся). Можно проверять их там: значение без вида отклонять как `::call/HostFailureError`, у которого уже есть `:message` и `:causes` [QSERR#site]. Тогда `<host-fn …>`, `::unknown`, `formOf → 'unknown'` и оба дефекта `::builtin/…` уходят одним правилом, без отдельного правила для `bind`, а `fromPlain` остаётся как способ, которым хост строит законный ответ.

```qlang
$ grep -n "return primitive(" core/src/runtime/verb.mjs
87:  if (readsState(primitive)) return primitive(served, ...inputValues, queryStateOf(state));
88:  if (readsPassedTags(primitive)) return primitive(served, ...inputValues, passedTags);
89:  return primitive(served, ...inputValues);
```

Цена — обход каждого ответа примитива, большие ответы хостов в том числе. Кроме того, хост, слова которого сейчас отвечают объектами JavaScript, сломается в одном релизе.
