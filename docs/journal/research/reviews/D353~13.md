- Пункт про cmd снимаю. На Windows строковая форма хука идёт в Git Bash. PowerShell используется только без Git Bash, cmd.exe хуки не использует (hooks, «Exec form and shell form», поле `shell`). На этой машине Git Bash есть, значит `$CLAUDE_PROJECT_DIR` раскрывается и хук работает.
- Без Git Bash остаётся риск. PowerShell читает `$CLAUDE_PROJECT_DIR` как пустую переменную: `Cannot find module 'C:\scripts\commit-hook.mjs'`. Упавший строковый PreToolUse-хук на Windows без Git Bash блокирует вызов (changelog 2.1.299), то есть каждый вызов оболочки.
- Документация советует для путей exec-форму: `{"type":"command","command":"node","args":["${CLAUDE_PROJECT_DIR}/scripts/commit-hook.mjs","--run"]}`.
- «На месте не запускался ни разу» снимаю. Правки хуков в settings.json подхватываются работающей сессией без перезапуска (settings, «When edits take effect»). Прошедший хук (код 0 без вывода) в транскрипте может не оставить следа. Настройки сохранены в 19:25 UTC, так что оба коммита ветки (89f6d06b в 19:33 UTC, c55c3e2f в 19:39 UTC) могли пройти через хук.
- «Не то дерево» документация подтверждает. После EnterWorktree `${CLAUDE_PROJECT_DIR}` указывает на исходный корень, а `cwd` во входе хука — на корень worktree (worktrees, «Hook paths don't follow the worktree»). `scripts/commit-hook.mjs:20-22` судит основную копию. Чекаут коммита хук может взять из `cwd` входа и из `-C dir` команды.
- Код 1 и таймаут хука не блокируют (fail open), пока не задан `"onFailure": "block"` (с 2.1.295). Хук, который не стартовал или упал проверкой, пропускает коммит без проверки.
