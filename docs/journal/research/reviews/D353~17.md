**2. Точка учит неверной форме.** grammar.peggy:507–510, D403.md:24–27; принцип «безопасно смотреть на ответ» (отказ должен давать верный сигнал).
- В позиции модификатора не-`get` сообщение называет `get /…`:
  - `"[{:age 2} {:age 1}] | sort .age" | parse !| get /message` → «…`get /age`»;
  - `[{:age 2} {:age 1}] | sort get /age` → `::vec/sort/key/KindNotTakenError`;
  - верная форма `sort /age` → `[{:age 1} {:age 2}]`.
- Вторая альтернатива называет «точкой одной» любую точку не перед именем и не перед цифрой. `.[0]`, `get ."a b"`, `..` → «`.` is no value: the value itself is `it`», а следование совету `[1 2] | it[0]` → «words are set off by whitespace…». D403 говорит только о «dot alone».

**3. Отказ `?` после ключа в кавычках, содержащего `?`, учит читать другой ключ.**
- Где: grammar.peggy:969, `written.replaceAll('?', '')` удаляет и `?` внутри кавычек. Против D403.md:20 и QSWRK#code: сообщение строится заменой по тексту, а не по сегментам пути.
- Проба: `"{:\"a?\" 1} | get /\"a?\"?" | parse !| get /message` → «…write `query /"a"`».
- При этом `get [~({:"a?" 1} | query /"a") ~({:"a?" 1} | query /"a?")]` → `[null 1]`.

**4. Новый квадратичный рост, внесённый веткой.**
- Где: grammar.peggy:825–826. `input.includes('\n', location().start.offset)` на каждом `~` и `::` прозы строкового дока сканирует до конца строки, а на последней строке до конца источника.
